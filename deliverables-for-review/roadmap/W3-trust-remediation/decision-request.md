本批只做架构复核范围内的整改，不自行推进阶段2/3、W4、正式发布或真实模型试验。

## 1. 契约与准入党

- 是否接受 `rkd-ai-design-option.v2`（含本批三处收紧）+ `admission` 作为 W3 的正式候选契约与唯一准入党？

## 2. 运行来源信任边界

- 现方案：受控服务持有落盘 HMAC 密钥（0600）+ append-only 记录，签发需真实观测字节，父链需仓储登记；消费者只拿只读验证能力。
- **残余风险**：能写服务目录者可伪造；没有接入 OS 服务/KMS/账号体系（本批明确不扩 NAS/账号）。
- 请裁定该边界对 W3 是否足够；若不够，需要单列"运行签发迁出进程/受 OS 保护"的任务，不与本批混做。
- 重启核验已实现（密钥缺失则历史记录保持 unknown），但未做跨机/多实例测试。

## 3. 用户可操作路径的场地绑定（阻塞）

`AIDesignOptionService.submit()` 的 site 仍由 `context_provider` 提供，尚未注入 v2 快照。后果：真实模型候选即使通过受控流水线，进入用户提交路径仍会走 v1 测试边界或直接失败。

请确认下一批是否以"项目输入→场地快照→submit 注入→候选 v2 持久化"为主线；在此之前，本批不声称正式用户路径已具备该门槛。

## 4. 真实模型试验

本批 0 次外部调用、0 费用、0 外发、未使用真实密钥。真实运行需要：

- 外发类别与数量上限；
- 费用上限与结算方式；
- 允许的端点（决定 `live_http` 判定）；
- 失败与重试的停止条件。

在获得明确授权前，`live_http` 分支只有代码与负向验证，没有真实调用证据。
