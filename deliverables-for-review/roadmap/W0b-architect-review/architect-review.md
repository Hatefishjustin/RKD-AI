## TEXT-01 / P1：自然语言目标被扩大、反转或遗漏

位置：`mvp/rkd_mvp/studio/revision_task.py` 的 derive_text_objectives、derive_objectives；调用路径为 orchestrator._revise_from_baseline。前端 StudioView.tsx:208 起只提交 text 和选定基线，不替用户提交结构化 objectives。因此不能用手工构造 objectives 的成功案例代替普通输入的验证。

### 1. 点名一个对象，却要求整个家具集合变化

独立输入：`把 F3 旋转到 -30 度，其他家具不动`。

实际解析：objects_scope=[furniture]、object_ids=[]、quantifier=all、target=-30；正确只修改 F3.rot 的候选被判 fail。原因是文字解析忽略句子内的 F3，调用 derive_text_objectives 时 object_ids=None，随后 all 聚合应用到整类家具。模型收到错误的程序目标后，还可能被引导修改全部家具以通过检查。

预期：F3 是唯一旋转目标；其他家具保留。对象不能明确绑定时应 unknown/pending，不能默默扩大成整类。只有用户确实说“所有家具”才允许全组范围。

### 2. 上限被解释成下限

独立输入：`主动线净宽不超过 2400mm`。

实际解析：comparator=min，target=2400。它没有识别“不超过”，直接使用宽度默认 min。结构化 max 测试通过不代表该文字入口正确。

预期：识别 max；至少/不小于→min，等于/恰好→exact。不支持、矛盾或含糊比较表达明确 unknown 或冲突，不得选择相反含义。几何测量的有限覆盖声明继续保留，不扩大成专业净宽合规。

### 3. 数值要求吞掉审美待确认项

独立输入：`主动线净宽至少 2100mm，同时整体更有设计感`。

实际只有 measurable，缺少 aesthetic/unknown 的独立待确认项。derive_objectives 只有在整条留言完全没有 produced 时才补审美目标。有数值或保留目标以后，其他未解析诉求可能消失。

预期：数值、保留、审美、未支持子句分别留来源片段和当前处置；“更有设计感”保持 unknown + user_confirmed=pending。程序通过可计算部分不能声称整条复合反馈已解决。

## 最小修复范围与验收

建立一条共用的“文字子句 → 对象绑定/比较符/目标或未解析待办 → 规则校验”路径。优先复用本次已有对象索引和保留绑定能力，不另建通用语义平台。明确对象 ID 和简单表达可以确定性解析；复杂表达可以保持未解析，不能用错误的默认值自称理解。若使用模型辅助解析，提案必须经过对象、字段、范围和来源核验；本次仍可本地桩验证，无需新增付费调用。

必须通过真实 HTTP /messages → /run，并至少一条浏览器正常文字输入；不得在验收脚本里偷偷补 objectives/locks 代替用户输入：

- 点名 F3 旋转，其余家具保持：只改 F3 通过，误改其他家具拒绝或明确未验证，不能自动扩成全组。
- 点名两个对象、明确所有对象、对象不存在、同名对象歧义：范围与未解析状态正确。
- min / max / exact 三种普通文字表达分别进入对应比较符，并有反向负例。
- 同条文字包含多个同类数值目标（例如 F1 与 F3 不同角度）：不得只取第一个匹配，无法表达时列出未支持部分。
- 数值 + 保留 + 审美：三类诉求都存在，审美始终 pending；可计算项通过不能吞掉未解析项。
- 同基线合并的矛盾要求要显式冲突或明确替代关系，不通过无限返工解决逻辑矛盾。

现有 17 例、15 项 HTTP 和相关回归保持。新增输出路径参数或采用独立路径，避免再次覆盖历史证据；这是测试脚本的小修，不是新增管理工作包。提交 `W0-文字反馈收口` 复核包后再判断 W0 放行。
