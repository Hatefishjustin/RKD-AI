# 六、n8n 部署与导入说明

> 适用环境：飞牛 NAS（fnOS）Docker。若 NAS 不支持 Docker，见文末降级方案。
>
> AI 模型与生图/CAD/效果图工具怎么选，见《09_设计工具AI选型/01_AI选型与部署简明方案.md》。

## 1. 部署步骤（约 1 小时）

### 1.1 部署 PostgreSQL（公司主数据库）

```yaml
# docker-compose.yml（与 n8n 同一 compose 文件即可）
services:
  db:
    image: postgres:16-alpine
    restart: always
    environment:
      POSTGRES_DB: design
      POSTGRES_USER: design
      POSTGRES_PASSWORD: <设置强密码>
    volumes:
      - /vol1/docker/design-ai/pgdata:/var/lib/postgresql/data
    ports:
      - "5432:5432"
  n8n:
    image: n8nio/n8n:latest
    restart: always
    environment:
      - GENERIC_TIMEZONE=Asia/Shanghai
      - TZ=Asia/Shanghai
      - N8N_SECURE_COOKIE=false      # 仅内网 HTTP 访问时需要
    ports:
      - "5678:5678"
    volumes:
      - /vol1/docker/design-ai/n8ndata:/home/node/.n8n
    depends_on:
      - db
```

启动：`docker compose up -d`。验证：浏览器访问 `http://NAS内网IP:5678`，首次打开按引导创建管理员账号（新版 n8n 自带登录体系，无需再配置基础认证环境变量）。

### 1.2 建表

```bash
# 将 02_数据模板/db_init.sql 上传 NAS 后执行
docker exec -i <db容器名> psql -U design -d design < /path/to/db_init.sql
```

验证：`psql -U design -d design -c "\dt"` 应看到 9 张表。

### 1.3 导入工作流

1. n8n 界面 → Workflows → Import from File，依次导入本目录 3 个 JSON。
2. 创建凭据：PostgreSQL（主机 `db`、端口 5432、用户/密码同上、数据库 `design`）；在 3 个工作流中把所有 Postgres 节点的凭据替换为新凭据（模板中的 `PG_MAIN` 为占位）。
3. 激活工作流，测试 Webhook：
   ```bash
   curl -X POST http://NAS内网IP:5678/webhook/issue-submit \
     -H "Content-Type: application/json" \
     -d '{"project_no":"HZ-26-001","found_by":"测试","description":"测试问题：墙面粉刷色号错误"}'
   ```

### 1.4 配置环境变量（.env 或 compose environment）

| 变量 | 说明 |
|---|---|
| `LLM_API_URL` | 大模型接口地址（OpenAI 兼容格式）：智谱 `https://open.bigmodel.cn/api/paas/v4/chat/completions`；DeepSeek `https://api.deepseek.com/chat/completions` |
| `LLM_API_KEY` | 对应平台申请的 API Key（Authorization 请求头） |
| `LLM_MODEL` | 模型名（以官网在售型号为准）：智谱日常用 `glm-5-air`、复杂任务 `glm-5`；DeepSeek 用 `deepseek-chat` |
| `DT_WEBHOOK_ISSUE` | 钉钉"施工问题群"机器人 Webhook |
| `DT_WEBHOOK_PROCURE` | 钉钉"采购与供应商群"机器人 Webhook |
| `DT_WEBHOOK_QUOTE` | 钉钉"报价与签约群"机器人 Webhook |
| `DT_WEBHOOK_BOSS` | 老板专用机器人 Webhook（群内仅老板和管理员） |

### 1.5 上线前必做

- 把工作流内 3 处 AI 提示词与 `03_AI角色与提示词/` 中完整版提示词对齐（JSON 内为精简版，正式版以文档为准并按输出格式要求同步）。
- 按 `07_风险与安全/` 配置 NAS 备份与数据库每日备份（`pg_dump` 定时任务）。
- 试运行 1 周每日巡检，确认钉钉机器人限流（每分钟 20 条）不触发；必要时合并消息。

## 2. 降级方案（NAS 不支持 Docker 时）

- **方案 A（推荐）**：n8n 云版（付费，约 20 欧元/月档）+ 阿里云 RDS PostgreSQL 基础版；数据在云端，NAS 仅存文件。
- **方案 B（零成本起步）**：完全不上自动化平台，用钉钉宜搭表单的"自动化规则+定时提醒"实现简化版问题登记与提醒，数据存宜搭/Excel；待条件成熟再迁移（字段按本包数据字典建，迁移零改造）。

## 3. 快速版与稳定版对应关系

| 工作链节点 | 快速版（第 1~2 周） | 稳定版（本包 JSON） |
|---|---|---|
| n1/s1 提交 | 钉钉宜搭表单 | Webhook（表单→n8n） |
| n2 AI 整理 | 老板/助理手动粘贴给 AI 助手 | HTTP 节点自动调用 |
| n4 入库 | 宜搭数据表/Excel | PostgreSQL |
| n6/n7 提醒 | 宜搭定时提醒/群机器人手动 | 定时巡检自动分级 |
| 审批 | 钉钉群口头/待办 | approvals 表+老板机器人 |
