# 十一、自动化边界、权限与数据安全方案

## 1. 自动化边界（全系统最优先遵守）

### 可以自动执行（AI+系统直接做，无需确认）

信息提取、会议总结、任务创建、文件归档、普通提醒、超期报警、进度汇总、报价漏项检查、周报生成、常规供应商催办、供应商评分公式更新、数据库登记。

### 必须人工确认（老板终审，AI 只准备材料）

是否接收客户、设计方向、正式报价、合同条款、材料品牌与替换、重大设计变更、施工质量认定、客户投诉、退款和赔偿、一切影响工期/成本/利润/客户关系的事项。

### 系统级红线（写死在工作流中，不可配置绕过）

1. 金额与利润只由公式计算（Excel/数据库），大模型输出中的任何金额仅作参考展示，不进入汇总公式。
2. AI 置信度 < 0.7 的记录进入"待人工确认"，不自动分派催办。
3. 报价版本只有 `已确认` 状态可发客户；`待审批` 状态的推送永远带毛利率红线提示。
4. 通知失败重试 3 次后转人工告警，业务数据永不因通知失败而丢失。
5. 删除类操作（删表、删项目目录）只能人工在数据库/NAS 执行，任何自动化流程无删除权限。

## 2. 权限矩阵

| 人员/系统 | 数据库 | NAS | 钉钉 | 大模型 API |
|---|---|---|---|---|
| 老板 | 全部读写 | 全部 | 全部群+审批 | 可用 |
| 行政/助理 | 业务表读写，无删除 | 除备份外读写 | 表单+群 | 经 AI 应用间接用 |
| 效果图/施工图设计师 | 无直连 | 对应项目目录读写 | 群消息 | 无 |
| 外包施工 | 无 | 仅 08/09 目录提交 | 相关群 | 无 |
| n8n | 业务表读写+编号函数 | 文件归档目录 | 机器人发送 | 调用 |
| Dify/AI 应用 | 只读知识库+指定表写入 | 无 | 无 | — |

数据库账号分两级：`design_app`（n8n 用，业务表读写）与 `design_admin`（人工维护用），应用账号无 `DROP/DELETE` 权限（用状态字段代替删除）。

## 3. 数据安全方案

| 风险 | 措施 |
|---|---|
| NAS 硬件损坏/误删 | 每日 pg_dump + 每周快照 + 每月异地/云备份；每季度恢复演练（见 NAS 规范第 4 节） |
| 客户隐私（电话、地址、合同） | 进入 AI 的文本先经脱敏规则（电话打码、姓名可保留姓）；合同与报价原件不上传任何云端大模型；Dify 知识库部署在内网 NAS |
| 商业机密（成本、利润、供应商价格） | 材料库/利润表文件仅老板+行政可见；数据库按账号隔离；AI 提示词明令禁止对外文案含成本利润 |
| 大模型 API 数据外流 | 选国内合规服务商并关闭"用于训练"选项；敏感字段（客户联系方式）默认不传，只在需要时人工放行 |
| 钉钉机器人滥用 | Webhook 加签保存于 n8n 环境变量，不进群聊；4 群分机器人限权 |
| 误操作自动化（错误群发/错分派） | 工作流先灰度：新规则先跑"仅记录不发送"模式 3 天，老板确认后再开启发送 |
| 停电/断网 | NAS 与 Docker 服务 `restart: always`；关键提醒有每日 9:00 巡检兜底，单次 webhook 失败自动重试 |
| 人员离职 | 权限随钉钉组织架构自动回收；数据库/盘密码每半年更换；交接清单进 00_公司知识库 |

## 4. 上线验收指标（风险与安全部分）

- 备份：连续 2 周备份任务 100% 成功 + 1 次真实恢复演练通过。
- 权限：外包账号尝试访问 06_报价与合同 被拒（实测）。
- 红线：构造一条"紧急问题"和一版"毛利率<25%"的报价，确认两条均强制进入老板审批。
- 审计：n8n 执行历史保留 ≥90 天，钉钉机器人消息可回溯。
