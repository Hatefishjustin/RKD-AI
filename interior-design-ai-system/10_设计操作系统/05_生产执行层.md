# 设计操作系统 · 05 生产执行层（受控 CAD + Geometry Lock 渲染 + 造价联动）

> 目标：生产层的每一只"手"都是**受控的**。AI 不自由编辑 DWG，而是由结构化设计数据/规则生成变更指令，再由受控 CAD Agent 通过 AutoCAD API 执行。效果图不允许 AI"幻想空间"，几何先锁定，AI 只做材质、色彩、灯光、软装、氛围。

## 1. CAD 执行：五级阶梯（从最稳到最灵活，逐级降级使用）

| 级 | 方式 | 说明 | 审批要求 |
|---|---|---|---|
| ① 固定操作 API | 执行代理内置的原子操作（改材质、移墙、增删点位、改标注、换图框…） | 参数即可调用，最安全最快 | 无需额外审批（CR 已批准） |
| ② 已验证脚本 | 脚本库中通过回归测试的脚本 | 处理复合操作（批量标注、整层更新） | 版本化管理，改动需重新过门 |
| ③ 参数化模板 | 标准节点/房间模板实例化 | 新建标准内容（标准前台、标准会议室） | 模板变更走 CR |
| ④ 受控生成脚本 | AI 按需求生成脚本，**必须过五道门后入库为②** | 覆盖新出现的重复场景 | 五道门（第 2 节） |
| ⑤ AI 临时脚本 | 一次性脚本，仅限沙箱 | 兜底，永不直接进生产 | 五道门 + 强制人工批准 |

**执行顺序固定：能用①不用②，能用②不用③……**每次执行在 CR 日志登记用了哪级、耗时、结果。

### DWG 操作的技术表述（纠正后）

DWG 不交给 LLM 自由发挥，但 AutoCAD 提供成熟的程序化能力：.NET/ObjectARX API 可创建、读取、修改 DWG 对象；Automation API 可批处理 DWG、运行插件与 AutoLISP 脚本；AccoreConsole 支持无界面执行。**受控 CAD Agent = 这些 API 的封装**，输入是 Design Hub 的变更指令（对象 ID + 属性新旧值），输出是新版本 DWG/PDF + 改动清单。

## 2. AI 脚本五道门（④⑤级必经，缺一不可）

```text
Generate 生成脚本（AI 只写代码，不执行）
   ↓
Static Check 静态检查（语法/危险 API 黑名单：删除整图/全选覆盖/外部网络）
   ↓
Sandbox Run 沙箱运行（副本 DWG，无网络，限时 60s）
   ↓
Output Validation 输出校验（改动对象集合 ⊆ CR 声明的对象集合；图纸可打开；版本号正确）
   ↓
Human / Policy Approval（入库为②级需人工；沙箱一次性使用可按白名单策略自动）
   ↓
Production
```

校验失败 → 脚本废弃并记录失败原因 → 知识库沉淀（同类需求下次生成时参考）。

## 3. 工作站执行代理（唯一的"手"）

一台 Windows 设计工作站上的常驻服务（NAS 上的 n8n 是大脑，工作站是手）：

| 接口 | 作用 |
|---|---|
| POST /hub/apply | 按 CR 变更集更新 Design Hub（唯一写入口） |
| POST /cad/run | 按阶梯①~⑤执行 CAD 变更，返回产物路径+diff |
| POST /render/queue | 渲染任务入队（确认图/终稿），带 Geometry Lock 参数 |
| POST /export | 导出图纸/材料表（绑定 Design Version 号） |
| GET /status | 工作站心跳（AutoCAD/SU/渲染器就绪状态） |

安全：仅接受 NAS 内网调用+Token 鉴权；所有调用写审计日志；失败重试 3 次后转人工。

## 4. 效果图：Geometry Lock 渲染管线

### 4.1 真实性优先级（不允许颠倒）

```text
几何真实性 → 空间布局真实性 → 材料真实性 → 灯光 → 艺术表现
```

先锁几何，AI 只处理后续层。**禁止纯文生图进入任何对外交付。**

### 4.2 Geometry Lock 锁定清单

墙体位置与厚度、门窗位置与尺寸、固定柜体、核心家具位置、层高、开间进深——全部来自 Design Hub/SU 模型导出的深度图（depth）与边缘图（canny/线稿）作为控制输入。AI 图像模型允许改变的只有：材质、色彩、灯光氛围、软装配饰、艺术表现。

### 4.3 两档出图 + 几何一致性检查

```text
确认图（分钟级，给客户选）
  SU/Hub 导出 depth+canny → SD/Flux + ControlNet（或即梦参考图生图）
  → Vision QA 几何一致性检查（06 文档）：对照原始 CAD/3D reference，
     检查墙体/门窗/家具位置/主要尺寸关系；严重偏差 → FAIL → 自动重新生成（≤3次）
  → 通过 → 拼对比图（旧 vs 新）发客户（S7 确认关）

终稿图（夜间队列，签发用）
  模型更新 → Enscape/D5/Blender 无界面批量渲染 → 后处理 → 绑定版本号归档
```

渲染任务记录（render_jobs）：控制图引用、模型版本、提示词、种子、QA 结论——保证可复现。

## 5. 造价联动（AI 不算钱）

```text
Hub 对象/属性变化 → 工程量重算（规则/公式）
  → 量差 × 材料库价格（数据库取数）
  → 变更报价单 CQ-xx（固定公式，沿用报价链模板）
  → AI 只负责生成报价说明与差异解释文字
```

CQ 编号规则：项目编号-CQ-序号（HZ-26-001-CQ-003），与报价版本表（Q 序列）分开，签发走同一审批引擎。

## 6. 文档与报告自动生成

变更影响报告（04 文档第 6 节）、施工交底单（对象级改动说明+图纸版本）、客户确认函（对比图+报价+确认按钮）——全部由模板+Hub 数据生成，人工只签发。
