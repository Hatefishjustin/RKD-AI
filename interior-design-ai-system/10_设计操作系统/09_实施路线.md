# 设计操作系统 · 09 实施路线（三阶段）

> 原则：先让"流程和数据跑对"（手动挡），再让"手"自动化（A 类闭环），最后规模化。每阶段独立可运行、独立有收益。

## 阶段Ⅰ · 手动挡（第 1~2 月）：证据与流程上线，生产暂由人工执行

| 周 | 任务 | 产出 |
|---|---|---|
| W1 | 执行 `07_数据模型`建 design_os 库；配置权限矩阵（试点项目全员）；企微 AI 客服接入（客户群迁移） | 库表+入口就绪 |
| W2 | 理解层 A1~A3 上线：所有需求先出 FACT/INFERENCE/ASSUMPTION+澄清问题；CR 状态机跑起来（S0~S8 人工推进） | 全变更 CR 化 |
| W3~4 | 决策层 B1~B2 上线（影响图谱先人工维护关键区域）；变更影响报告模板启用；审计链四环齐套检查 | 老板用影响报告拍板 |

**里程碑**：100% 变更有 CR 编号与审计链；证据表 append-only 生效；"厨房太压抑"类需求必须经过澄清才能动手。

## 阶段Ⅱ · A 类闭环（第 2~3 月）：Design Hub + 执行代理 + 门禁自动化

| 任务 | 说明 |
|---|---|
| Design Hub 建库 | 新项目立项即建；存量项目"遇到变更、局部入库" |
| 工作站执行代理 | 一台 Windows 设计机部署常驻服务（AutoCAD+SU+渲染器），接口见 05 文档第 3 节 |
| Top20 固定 API/已验证脚本 | 从阶段Ⅰ CR 日志统计高频变更（换材质/家具微调/改标注/批量出图），逐个固化为①②级 |
| Geometry Lock 确认图 | depth/canny 控制生图 + D2 几何 QA，进 S7 客户确认 |
| 造价联动 | 量差→公式→CQ 变更报价单，接报价链签发 |
| 门禁开启 | gate_check 全绿才 AUTO；AUTO 附事后告知卡（24h 可叫停回滚） |

**里程碑**：第一个门禁全绿的变更端到端无人执行（客户确认→图纸/渲染/报价自动产出→签发）。

## 阶段Ⅲ · 规模化（第 3~6 月）：参数化模板 + 施工证据闭环

| 任务 | 说明 |
|---|---|
| 企业空间参数化模板 | 2~4 周投入，新项目全参数化（制图自动化率的前提） |
| 渲染夜间队列 | Enscape/D5/Blender 无界面批量渲染终稿 |
| 施工证据闭环 | 验收标准（照片点位清单）随任务下发，D4 核验，隐蔽工程强制人工 |
| 影响图谱自动维护 | CR 执行自动建边；每周孤儿/断边校验 |

**验收指标**：变更响应 ≤4 小时（受理→产物）；门禁全绿变更 100% 自动执行；自动执行占总变更比例 ≥60%；QA 一次通过率 ≥80%；审计链可回溯率 100%；客户"我没让你改这个"类争议可在 2 分钟内定责。

## 与现有 30/90 天计划的关系

- 第 1 个月的 MVP（三链+钉钉+NAS）**不变**，照常执行——它是 OS 的底座。
- OS 阶段Ⅰ从第 2 个月开始，与原"第 2 个月设计协同"合并（会议纪要/修改清单由理解层吸收）。
- 原阶段 5/6（设计协同、交付扩展）的内容分别并入 OS 阶段Ⅱ/Ⅲ。

## 增量预算（量级，以官网/报价为准）

| 项 | 量级 |
|---|---|
| 执行代理开发 | 自研 5~8 人日（FastAPI/Node + AutoCAD API 封装） |
| 大模型 API | 文字每月几十~几百元；生图按张（liblibAI/即梦） |
| 工作站 | 现有高配机 0 元；新购 5千~8千 |
| 企业微信 | 基础免费档可起步 |

## 风险与对策（摘要，详见 07_风险与安全 增补）

1. 团队绕过 CR 直接改图 → Hub 每日对账 + 版本不一致告警。
2. 澄清问题惹烦客户 → 一次≤3问带选项，AI 客服话术由老板审定。
3. 脚本缺陷改坏图纸 → 五道门 + 沙箱 + 对象白名单 + 版本回滚。
4. 证据录入流于形式 → 存证自动化（企微回调即存证），无人工负担。
