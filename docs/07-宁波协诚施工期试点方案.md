# 宁波协诚集团样品展厅施工期试点方案

## 1. 试点目标

用一套真实项目资料验证系统能否稳定完成“资料登记、空间识别、预算归集、现场证据留痕和人工确认”五件事。试点只验证可追溯和可恢复的生产链，不把未经确认的图纸或报价直接当作施工指令。

## 2. 当前输入与边界

首批输入位于 `fixtures/ningbo-xiecheng/2026-09/`，包括 1 个 DWG 平面图原件、1 页 A3 平面图、1 份旧版预算表和 3 张现场照片。详细解析、指纹、用户决策和缺口见同目录的 `资料接入报告.md` 与 `样本清单.json`。

当前允许的输出：

- 图纸版次和预算版次登记；
- 图面尺寸、功能区和照片观察的初始对象；
- 预算汇总、分项、家具采购项和待定费用的结构化记录；
- 来源、哈希、解析状态、不确定性和人工确认任务；
- 预算归集与来源金额的独立校验报告。

当前禁止的输出：

- 未经现场复测的施工放样尺寸；
- 未经客户确认的最终方案、材料下单或施工指令；
- 把机电、消防、税金或未报价项目自动填成 0；
- 把优惠价和工程总造价同时当作合同基线；
- 在税率未确认时，依据原表的 10% 待定值自动拆分含税金额；
- 依据照片推导承重、层高、朝向或机电点位。

## 3. 分阶段流程

### 阶段 A：资料登记（已完成）

1. 复制原件到项目隔离目录，不覆盖原件。
2. 计算 SHA-256，生成 `source_asset` 记录。
3. 保存文件类型、版本、页数/工作表、解析状态和隐私分类。
4. 对 DWG、PDF、旧版 XLS 和照片分别记录解析警告。

完成标志：清单可读、哈希稳定、原件可回放。

### 阶段 B：施工图提取与例外确认（结构解析与首轮语义映射完成）

系统优先从施工图提取：

- 现场长宽、层高、门窗洞口、柱网、楼梯和不可拆改构件；
- 强弱电、空调、消防和给排水点位；
- 图纸功能区与现场照片的对应关系；

只有施工图缺项、图内互相矛盾或图纸与现场照片明显冲突时，才由项目负责人补充或确认。业务范围按以下已确认决策执行：

- 预算基线采用用户确认的 `600,000 元优惠价`；
- 机电设备和消防改造不纳入本次范围；
- 税金纳入 600,000 元基线，但税率、税额和合同含税表述仍需确认；
- 客户需求暂未明确，由设计方案提出初始需求，再由项目负责人/客户人工确认；
- 品牌规范、材料样板和交付时间。

完成标志：所有关键技术信息都有施工图来源定位；例外项有确认人；无法提取的值保留 `unknown`，不以 0 替代。

### 阶段 C：统一模型回放（主平面候选已提取，待对象合并和二次校验）

1. 已从登记 DWG 读出毫米单位、57 个图层、94,706 个图元、3,506 个文字类对象和 1,152 个尺寸对象，并完成墙体、门窗、家具、灯具、天花、给排水等首轮专业语义映射。
2. 已通过 PDF 核对层 `8` 的 `17,920 mm × 26,170 mm` 等尺寸证据；块关系分析将 94,706 个存储图元分为 40,334 个可达图元、53,032 个未使用块定义和 1,340 个无可靠所有者图元。
3. 4 个复杂层的 4,512 个可达记录已完成定位：主平面内只有 `250` 层 5 条线和 `155` 层 1 条线；`图层 1` 和 `AM_1` 不在主平面。6 条线保持辅助证据状态，不自动分配专业类别。
4. 已用两个独立尺寸层将主平面锁定在 `26,169.582 mm × 17,920.175 mm` 区域，并提取 831 个直接模型候选；570 个属于当前装修设计范围，261 个机电候选按项目决定排除。
5. 105 个插入块已完成基点、平移、缩放、旋转、镜像、正/反向平面坐标系和最多两层嵌套展开；候选仍是 CAD 基础图元，不得直接当作构件数量或工程量。
6. 570 个当前范围候选已归为 133 个几何组；跨类别不合并，机电排除项不进入分组，所有组保持 `quantity_status=not-ready`。
7. 使用 Shapely 2.1.2 / GEOS 3.13.1 对墙、天花和地坪可信线元多边形化，得到 70 个闭合区候选；墙 8 个（5.746 平方米）、天花 58 个（37.380 平方米）、地坪 4 个小区（0.177 平方米），全部保持不可计量状态。
8. 由于填充、尺寸关联和动态块存在解析兼容诊断，已接入同源 AutoCAD 2013 DXF 并完成摘要、基础块展开和逐对象核对；640 个同句柄候选全部匹配，非交集项已按类型建立抽查队列。专业抽查前禁止把边界和尺寸升级为 `construction_verified`。
9. 将 PDF 的功能区作为初始标签，与可编辑几何建立来源关系。
10. 将预算行映射为工程量、主材、辅材、人工、家具和采购项。
11. 将照片挂接到空间或观察点，保留拍摄文件指纹。
12. 生成一份“已确认、推断、待补、冲突”的差异报告。

完成标志：空间、预算和照片可以通过项目 ID、版次和来源资产互相追溯。

### 阶段 D：施工期变更回放（待变更单）

每次现场变更必须使用独立的变更单编号，记录变更原因、影响空间、影响工程量、预算差额、审批人和生效版次。变更未审批前不得覆盖原预算和原图纸。

完成标志：可以从任一成果版本回放到当时有效的图纸、预算和审批证据。

## 4. 自动校验与停止条件

| 校验 | 通过条件 | 不通过时的动作 |
| --- | --- | --- |
| 来源完整性 | 所有输入都有哈希和来源路径 | 停止导入，要求补登记 |
| 尺寸可信度 | 施工尺寸来自已解析施工图，缺项或冲突已人工确认 | 标记 `drawing_unverified`，禁止放样 |
| 预算归集 | 基础工程 `244,640.00`、主材 `322,728.50`、家具 `48,940.00` 可回算 | 生成差异项，不自动修正金额 |
| 总价口径 | 合同基线只选择一个金额口径 | 阻止生成合同/采购输出 |
| 范围 | 机电和消防标记为 `excluded` | 禁止自动生成对应采购或施工任务 |
| 税金 | 税金纳入基线，税率/税额有明确合同依据 | 税率未确认时阻止税额拆分 |
| 证据关系 | 每个关键空间和变更都有来源资产或人工确认 | 输出缺失证据清单 |
| 权限 | Agent 只能提出建议，人工角色才能确认 G2/预算基线/变更 | 拒绝命令并记审计事件 |

## 5. 试点验收指标

- 资料重启回放后哈希、版本和对象 ID 不漂移。
- 预算明细到汇总的金额差异为 0，待定项单独列出。
- 任意一个未知尺寸、待定费用或冲突对象都能在界面和 API 中被查询到。
- 删除或替换源文件不会抹掉历史版本和审计记录。
- 同一命令重复提交不会重复创建成果或重复计费。
- 未通过人工确认时，不产生“可施工”或“已审批”状态。

## 6. 下一批材料清单

优先级从高到低：

1. 4 个复杂层定位、第一轮拓扑分析、同源 DXF 摘要/基础块展开和 640 个共同候选逐对象核对已完成；下一步优先抽查 DWG 独有的 25 个填充和 35 个块证据，以及墙、地坪、固定家具、天花对应的 34 个当前范围非交集项，再确认 133 个几何组和 70 个闭合区候选；
2. 施工图解析后产生的缺项或冲突由你确认（没有例外时无需提供）；
3. 由设计方案提出的初始需求清单及客户确认记录；
4. 税率、税额和合同含税表述确认；
5. 施工计划、变更单或历史审批记录；
6. 另外 3 个已完成企业空间项目，用于建立跨项目金标准。

## 7. 试点结束条件

只有在阶段 B 的施工图提取和例外项确认完成，阶段 C 至少完成一次 CAD 映射，阶段 D 完成一次变更回放，并通过本方案的停止条件和回归测试后，才允许把本项目标记为“试点完成”。
