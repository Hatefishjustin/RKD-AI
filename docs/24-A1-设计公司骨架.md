## 这套东西是什么

一个最小可运行的「AI 室内设计公司」：5 个干活的人 + 1 个协调，共用一张项目工作台。
不是固定流水线脚本 —— 每个人是一次独立的模型调用，有自己的岗位提示、工具白名单和输出契约；
所有交接、讨论、评审、逐条回应、闸口都落在同一个数据库里，网页上能回放。

| 角色 | 姓名 | 岗位 | 能调用什么 |
| --- | --- | --- | --- |
| P | 林致远 | 项目经理（拆活、派活、开闸口） | 只读工作台 |
| D1 | 陈默 | 需求与任务书 | 场地、需求 |
| D2 | 周敘 | 空间规划 | 场地、需求、规范、家具目录、几何校验 |

| R | 傅之衡 | 设计总监（只评审，不设计、不批准） | 场地、需求、规范 |

## 一次 A1 回路做什么

1. **P** 拆解这一轮：做什么、交给谁、什么算做完（`task`）
2. **D1** 出任务书：目标、必须项、场地事实、推断、缺口（`artifact: brief`）
3. **D2 ↔ D3 动手前讨论**（`discussion` ×2，对应 STD-007）
4. **D2** 出两个拓扑不同的候选，每个都自检 `validate_plan`（`artifact: spatial-plan` ×2 + 缩略图）
5. **R** 逐条评审：问题挂到具体对象、引规范编号、给改法（`review`）
6. **D2** 逐条回应（接受/不接受 + 理由）并出修订版 v2（`revise` + `artifact` revision=2）
7. **P** 开闸口，等老板点（`gate`）

全程不自动通过；总监只能写 `advance`（建议）或 `revise`（打回）。

## 怎么跑

```bash

PYTHONPATH=mvp ./.venv/Scripts/python.exe -m rkd_mvp.studio.server

# 2) 工作台（127.0.0.1:8080）
PYTHONPATH=mvp ./.venv/Scripts/python.exe mvp/run_api_server.py

# 3) 浏览器打开，进入「设计公司」页
http://127.0.0.1:8080/?view=studio
```

真实回路的前置条件：当前会话环境变量里有 `RKD_AI_API_KEY`（可选 `RKD_AI_BASE_URL`、`RKD_AI_MODEL`）。
密钥不写入任何文件；未配置时点「开一轮」会明确返回 409，不会假装跑过。

预算：每次回路 ≤ 600,000 tokens，单项目 ≤ 2,000,000 tokens。超了停下并开闸口问你，页面顶部实时显示本轮用量。
