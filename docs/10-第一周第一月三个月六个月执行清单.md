# 给技术小白的第一周、第一月、三个月和六个月执行清单

> 2026-09-29 已更新推进顺序：本文时间清单保留为历史规划。当前依据 [产品交付执行计划与设计](13-产品交付执行计划与设计.md) 按可验收批次推进；用户当前无需补资料，下一参与节点是打开 M1 实际试用。不要沿用本文早期清单重新进行需求访谈或索取整批历史项目。

版本：V1.0  
日期：2026-09-19

## 1. 先看结论

你不需要学写代码，也不需要每天盯着开发人员。你的核心工作只有四类：指定谁负责、提供真实资料、确认少量商业/专业口径、在关键节点验收。

实施团队负责开发、部署、迁移、测试和修复；系统负责自动整理、生产、校验、交接和留痕。正式报价、合同、施工图发布、重大变更和最终验收仍由有责任的人点击确认。

## 2. 第一周

目标：把项目从“设计构想”变成可以管理和验收的正式实施项目。

### 你需要做

- [ ] 指定 1 名内部项目负责人，能代表公司协调资料和验收。
- [ ] 指定设计、施工图、商务财务三个专业责任人；可以由现有 6 人团队兼任。
- [ ] 确认五个人工闸口由谁批准、谁是替补：承接、设计冻结、报价合同、施工图发布、重大变更/验收。
- [ ] 确认宁波项目 `600,000 元` 是含税基线；税率、税额和合同文字暂时保留待确认。
- [ ] 同意正式状态以后只在系统/钉钉入口生效，微信继续沟通但不能作为唯一审批记录。

本周你不需要再提供施工图里已有的尺寸和点位，也不需要购买服务器或模型 API 套餐。

### 实施团队需要做

- [ ] 确认产品、技术、前端、AI/工作流、CAD/BIM、QA 和 DevOps 责任人。
- [ ] 建立需求、风险、决定、版本和缺陷登记表。
- [ ] 固定当前数据合同、命令、事件、状态机和五个闸口。
- [ ] 盘点 NAS、网络、域名、钉钉、CAD/BIM 软件和账号，但不改生产配置。
- [ ] 建立开发、测试、预发布、生产四套环境清单和密钥管理规则。
- [ ] 对宁波样本做现有自动测试和结果回放，记录基线。

### 系统自动做

- [ ] 校验已接入文件指纹，保证原件未被覆盖。
- [ ] 回放 DWG 解析、图层映射、主平面定位、块展开和几何归组。
- [ ] 输出范围内、排除项、未知项、风险和后续任务。
- [ ] 保留每一步使用的版本、来源和测试结果。

### 第一周完成标准

- 有一个明确负责人名单，不再出现“大家都负责”。
- 五个闸口和替补人确定。
- 开发团队、范围、环境和验收方式明确。
- 当前 51 项以上自动测试通过，宁波样本可以重复生成同样结果。
- 没有人承诺“30 天全自动公司”或直接拿未验证图纸施工。

## 3. 第一个月

目标：完成标准化、金标准准备和可恢复的平台底座，不追求漂亮的大而全界面。

### 你需要做

- [ ] 提供 3 个已经完成的企业空间项目，优先选择资料相对完整、类型有代表性的项目。
- [ ] 每个历史项目尽量包含：需求/设计任务书、量房或原始图、CAD、模型、效果图、施工图、材料、报价、变更和最终照片。
- [ ] 确认公司常用的图层、图框、编号、材料、报价、图纸深度和文件命名规则。
- [ ] 与财务确认“施工利润约 20%、设计利润约 60%”分别是毛利率还是成本加成率。
- [ ] 确认第一条新项目试点，不选择工期已经失控或资料严重缺失的项目。
- [ ] 每周参加一次 30-45 分钟验收会，只处理阻断决定。

### 实施团队需要做

- [ ] 建立项目数字线程、身份、权限、文件版本、审计、异常中心和持久工作流。
- [ ] 把 3 个历史项目整理成只读金标准，记录允许误差和专业人员签字。
- [ ] 实现本地/测试环境的 PostgreSQL、对象存储和消息/工作流基础设施。
- [ ] 建立钉钉开发入口和模拟通知，不连接真实采购、付款或客户发布。
- [ ] 完成跨租户、幂等、重复消息、重启恢复、备份和恢复测试。
- [ ] 评估第二 CAD 解析引擎或原 AutoCAD 受控执行器，完成授权和安全方案。

### 系统自动做

- [ ] 导入和去重资料，记录来源、版本和缺失项。
- [ ] 将历史项目按需求、空间、模型、图纸、BOQ、报价和变更建立关系。
- [ ] 在影子模式运行 Agent，不向客户、供应商和施工方发送真实信息。
- [ ] 统计失败、人工修改、处理时间、成本和一致性差异。

### 第一个月完成标准

- 至少 1 个完整历史项目可以端到端回放，另外 2 个已进入整理。
- 平台重启后项目、任务、版本和审计不会丢失。
- 客户、供应商、施工方和内部人员的权限边界有自动负例测试。
- 数据库和文件至少完成一次实际恢复，不只写备份方案。
- 宁波 CAD 有第二引擎/原 CAD 软件的抽样验证计划。

## 4. 三个月

目标：交付第一条真实但受控的纵向生产链，让客户需求只输入一次，系统自动向后交接。

### 你需要做

- [ ] 选择一个新企业空间项目进行影子运行。
- [ ] 在 G1-G5 五个闸口按系统任务确认，不通过微信口头代替。
- [ ] 每周只看老板驾驶舱的重大质量、成本、工期和运行异常。
- [ ] 让设计、施工图和商务人员真实记录系统成果的修改，不要为了“成绩好看”绕开记录。
- [ ] 决定哪些低风险任务可以从影子运行升到受监督自动。

### 实施团队需要做

- [ ] 完成需求结构化、设计任务书、空间方案、模型草案、图纸/BOQ 草案和模拟发布的自动交接。
- [ ] 完成命令网关、版本锁、幂等、异常队列、人工接管和四级停用开关。
- [ ] 将 CAD/BIM/渲染/报价执行器接入带版本的数据合同。
- [ ] 对需求-模型-图纸-BOQ-报价执行自动一致性检查。
- [ ] 在预发布环境完成权限、安全、故障、迁移、回滚和灾备演练。
- [ ] 建立第 9 项评估驾驶舱，分开显示计划审批和纠错救援。

### 系统自动做

- [ ] 从一次客户需求输入形成结构化需求和补问清单。
- [ ] 自动把上一步正式版本交给下一 Agent/执行器，不要求人员下载再上传。
- [ ] 自动生成候选方案、模型、图纸、BOQ 和报价草稿。
- [ ] 对不一致、未知、越权和高风险动作停止并创建任务。
- [ ] 自动记录每个任务的自主等级、人工分钟、缺陷、版本、成本和结果。

### 三个月完成标准

- 一个新企业空间项目可以从需求跑到可审阅成果，全程不依靠人工搬运文件。
- 系统失败后可以重试、恢复或人工接管，不重复发布和计费。
- 外部动作仍以模拟或严格白名单为主；正式施工图和报价必须经过责任人。
- E0 缺陷为 0，E1 未关闭不得进入下一闸口。
- 第一条链路的真实自主率、受监督率和人工纠错时间有可信数据，而不是估计。

## 5. 六个月

目标：形成企业空间的专业生产基线，并开始小范围真实使用，不追求跨所有项目类型。

### 你需要做

- [ ] 审批企业空间的图纸深度、效果图质量、报价和材料标准版本。
- [ ] 根据至少 3 个项目的指标，决定哪些任务可以开放真实低风险自动执行。
- [ ] 确认云资源、CAD/BIM/渲染软件、模型 API 和运维的年度预算。
- [ ] 确认正式值班、事故响应、数据责任人和离职交接制度。
- [ ] 决定第二类项目优先扩展商业/办公还是住宅，不同时全面铺开。

### 实施团队需要做

- [ ] 完成企业空间规划、参数化模型、效果图和施工图的专业执行器基线。
- [ ] 完成 BOQ、价格快照、报价、税和利润确定性计算与独立复算。
- [ ] 完成钉钉内部任务/审批和客户、供应商、施工方受限入口。
- [ ] 在 1-2 个项目中灰度真实低风险动作，保留全局停用和回滚。
- [ ] 完成安全测试、容量测试、恢复演练和生产运维手册。
- [ ] 对模型、执行器、规则和供应商升级建立回归和灰度流程。

### 系统自动做

- [ ] 自动管理项目阶段、任务、版本、风险和异常升级。
- [ ] 自动生成和校验同一模型来源的效果图、图纸、工程量和报价草稿。
- [ ] 自动跟踪采购下单、收货、分派、施工问题和变更传播。
- [ ] 自动生成老板只需处理的高风险审批摘要。
- [ ] 自动比较版本、项目和执行器的质量、时间、成本和人工干预。

### 六个月完成标准

- 企业空间至少有 1 个真实项目在受控生产中使用系统主要链路。
- 客户需求、模型、图纸、BOQ、报价和变更能够互相追溯。
- 正式发布、合同、付款和重大变更均有授权人与审计记录。
- 数据库、对象存储和 NAS 通过恢复演练，NAS 不再是未经验证的唯一副本。
- 只有连续多个同类项目达标的任务才扩大自主权限。

## 6. 你需要准备的材料时间表

| 时间 | 需要你提供/确认 | 没有时系统怎么做 |
| --- | --- | --- |
| 现在 | 暂时无需新增材料 | 继续完成代码、合同、测试和宁波样本分析 |
| 第一周内 | 内部负责人、五个闸口和替补人 | 先用角色占位，不开放正式审批 |
| 第一个月内 | 3 个历史企业空间项目 | 只建立局部基线，不扩大自主权限 |
| 商务模块验收前 | 税率/税额/合同含税文字、利润口径 | 保留 unknown，阻止正式报价/利润结论 |
| 第二 CAD 校验前 | 原 CAD 软件可控环境或第二引擎授权 | 维持 drawing-unverified，不生成施工状态 |
| 真实灰度前 | 钉钉、域名、云、对象存储、模型/API 和专业软件账号 | 使用模拟适配器，不产生外部副作用 |
| 变更闭环验收前 | 一份真实变更单和审批证据 | 可演示模拟流程，但宁波试点不标完成 |

## 7. 你暂时不要做的事

- 不要先购买大量 AI 套餐、GPU 或新 NAS。
- 不要让开发团队直接把低代码流程当长期业务核心。
- 不要把未验证的 CAD 解析结果直接算工程量或用于施工放样。
- 不要把微信聊天截图当正式审批的唯一证据。
- 不要为了追求“全自动”取消报价、施工图、重大变更和验收责任人。
- 不要一次把企业空间、住宅、酒店、餐饮等所有类型同时上线。

## 8. 每周只问实施团队这八个问题

1. 本周哪条真实业务链跑通了？证据在哪里？
2. 哪些步骤仍需要人工复制、下载、上传或重复录入？
3. 有多少失败、重试、人工纠错和救援？
4. 有没有 E0/E1 缺陷、越权或错误外部动作？
5. 模型、图纸、BOQ 和报价是否来自同一版本并通过交叉校验？
6. 数据是否实际恢复过，还是只显示“备份成功”？
7. 本周新增成本是什么，属于开发、软件授权、云资源还是模型调用？
8. 下一周需要我做的决定是什么，最晚何时决定？

如果团队只能展示页面、聊天回答或宣传视频，却不能展示版本、测试、失败恢复和真实成果差异，说明项目还没有达到可生产状态。
