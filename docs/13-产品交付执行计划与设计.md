# RKD AI 产品交付执行计划与设计

版本：1.0  
日期：2026-09-29  
依据：用户要求先交付可操作系统、再实测迭代；完成架构复审后，用户要求固化计划以便后续 AI 连续执行。  
性质：当前实施基线；本文描述待建设能力，不表示这些功能已经实现。  
动态状态：[`PROJECT_STATUS.md`](../PROJECT_STATUS.md)；接管约定：[`AGENTS.md`](../AGENTS.md)。

## 1. 目标与当前判断

最终产品是一个统一的数字化室内设计公司生产系统：需求输入一次，设计、模型、图纸、工程量、报价和施工交付通过结构化数据及成果自动交接。它持续保留正式商业和专业责任人的审批。

当前仓库处于工程验证原型阶段。已有架构文档、参考后台、真实 CAD/DXF 分析代码和宁波样本；尚无可操作前端，上传、计算、专业生产和文件下载尚未接成产品闭环。旧文档中 95%/96% 不再作为当前进度依据。

实施分为 M1—M5。M1 先交付本地工作台；M2 紧接着证明模型变化可以驱动实际数量、金额和成果变化；M3 扩展设计生产；M4 接采购施工；M5 完成团队使用和受控生产验收。不能把 M1 当作最终目标，也不能把 M5 的全部条件提前作为 M1 开工门槛。

## 2. 固定业务口径与资料使用

| 事项 | 当前执行口径 | 边界 |
| --- | --- | --- |
| 宁波项目基线 | 含税总价 600,000.00 元 | 原预算“不含税”表述保留为来源冲突，不覆盖原件 |
| 试用税率 | 5%，来自用户本次指定口径 | 不是适用税制或发票的专业结论；正式文件另有财务核验状态 |
| 按上述口径拆税 | 未税 571,428.57 元，税额 28,571.43 元 | 固定公式计算，不再要求用户提供可计算的税额 |
| 施工利润约 20% | 成本加成率 20% | 同一税口径下，售价 = 成本 × 1.20 |
| 设计利润约 60% | 成本加成率 60% | 同一税口径下，售价 = 成本 × 1.60 |
| 机电、消防 | 不在本次范围 | 排除不是数量为 0，保留原始证据 |
| 设计需求 | 可根据现有方案生成初稿 | 初稿与客户已确认需求分开 |
| 原始资料 | 已有 DWG、DXF、PDF、预算 XLS、3 张照片 | 足够开发 M1，无需重新上传 |
| 后续历史项目 | 用于跨项目准确率和专业评估 | 当前不索取，不作为开发或本地试用前置条件 |

本轮只固化实施口径。现有 `样本清单.json` 等历史元数据仍有税率 pending 字段；M1-04 接入运行项目时，通过有来源的 Decision/Assumption 记录应用上述口径，并保留源表冲突，不能盲目使用旧字段或回写原始预算。

宁波项目是实际在建项目样本，适合文件、预算、问题、施工协同验证。M2 使用独立、明确标记的规则几何测试项目，不把测试面积或测试模型写成宁波实际构件。没有历史项目不妨碍建立计算测试例，但不能据此宣称通用识别准确率。

| 里程碑 | 交付结果 | 必须证明 | 当前外部依赖 |
| --- | --- | --- | --- |
| M1 本地可操作版 | 可启动、保存、预览、检查、试算和导出的工作台 | 第 10 节 U01—U10 全部有实际验收证据 | 无需新资料或生产账号 |

| M4 采购施工闭环 | 订单草稿、收货、分派、问题、变更、验收 | 数量守恒，变更影响可追踪；真实外部动作按权限开启 | 真实闭环验收时才需要相应业务记录 |

M5 的权限与备份设计在 M1 预留接口；多人共享或真实外部发布前必须完成相应硬化，不必等所有 M4 功能完成后才修安全。各阶段允许无冲突工作并行，验收不能跳过。

日历工期在 M1 第一条浏览器→数据库链路完成后，根据实际开发速度更新。历史多人团队的周期/预算是情景估算，不是当前承诺；用户无需先招聘团队或筹齐全部资源才能开始本地版。

## 4. M1 页面与交互设计

### 4.1 首次打开

用户双击项目启动入口，程序检查本地运行环境并打开浏览器。首页直接显示已接入的宁波项目；提供新建项目入口，无需先填写问卷、设置生产账号或提供新文件。

首次开发子交付至少打通“新建项目→保存→刷新仍存在”，同时开始真实页面。不能先连续完成数轮不可见基础设施才出现首屏。

### 4.2 导航

全局只保留项目列表和设置。项目内包含五个工作区：

| 页面 | 信息与操作 | 完成后应发生什么 |
| --- | --- | --- |
| 项目概览 | 项目名称、范围、预算基线、最近活动、下一项可执行任务 | 进入实际工作，无虚构完成度和空指标墙 |
| 资料与图纸 | 文件列表、来源、版本、上传、PDF/照片预览、原件下载 | 文件真实落盘；CAD 不可预览时仍可看对应已有 PDF |
| 检查与问题 | CAD 现有检查、预算冲突、来源定位、处理记录 | 可筛选、打开来源、记录处置；“已查看”不等于专业批准 |
| 预算与报价 | 源预算明细、可编辑工作副本、成本试算、加成、税、差额 | 保存新修订，实际计算，未知成本不自动显示利润 |
| 成果与任务 | 后台进度、失败原因、允许的重试/取消、导出、历史成果 | 返回真实成果文件，显示输入版本和生成时间 |

界面默认中文。专业错误翻译为可执行说明，详细技术日志折叠显示。表格支持清晰的数量、单位、单价和来源；不将每个字段变成独立卡片。完成、失败、等待和未知状态使用文字加视觉提示，不能只靠颜色区分。

### 4.3 数据显示原则

- 已有真实文件、示例模型、手工输入、程序计算、AI 建议在必要位置显示来源，不能混成已确认事实。
- 上传进度与解析进度分开。格式暂不支持时，文件仍已保存，展示具体限制，不阻断整个项目。
- PDF 是本期可靠的图面预览路径；M1 不承诺在浏览器中完整编辑任意 DWG/DXF。
- 预算原件只读；编辑发生在工作副本。原表总计、用户合同目标和试算总计分别显示。
- 刷新、切换页面后保留服务器已保存状态；保存失败要明确提示。并发修改冲突由用户选择处理，不静默覆盖。
- 用户处理一条问题后保留理由、操作者和时间；不能通过关闭普通问题自动发布报价或批准构件。

## 5. 技术结构与选型

### 5.1 本地结构

```text
浏览器工作台
    ↕ 同源 HTTP API
Python 模块化业务后端
    ├─ 项目、资料、问题、商务、成果服务
    ├─ 命令校验、版本控制、审计、事务
    ├─ SQLite 关系表 + 独立文件目录
    └─ 持久任务队列 → 受控 Worker → CAD / 计算 / 导出
                                      ↓
                              结果校验与成果登记
```

后续 AI、建模、制图、渲染执行器接同一作业与成果接口。AI 输出建议或结构化草稿，业务服务验证后落库；执行器不直接改变合同、审批或发布状态。

### 5.2 默认实现选择

| 层 | 选择 | 理由及约束 |
| --- | --- | --- |
| 前端 | React + TypeScript + Vite | 支持表格、文件预览及后续几何交互；构建后静态文件由后端同源提供 |
| 后端 | Python + FastAPI | 复用现有 Python 分析模块；将业务逻辑从参考 HTTP 实现迁入明确服务边界 |
| 本地存储 | SQLite 标准库、版本化 SQL 迁移、Repository/Unit of Work | 一个命令一个事务；连接由执行线程内创建使用，不共享全局连接 |
| 后台任务 | 同一应用管理的单 Worker；CAD 子进程隔离 | 队列、租约、输入和结果持久化；M1 不引入额外消息平台 |
| 文件 | 项目本地目录 + 元数据索引 | 原件不可覆盖，派生文件先临时写入、校验后原子落位 |
| 金额 | Decimal，数据库存整数分或规范十进制文本 | 数量高精度，金额明确舍入，JSON 金额使用十进制字符串 |
| 首版报告 | 自包含可打印 HTML 报告 + UTF-8 CSV 明细 | 下载真实字节，可独立打开；不依赖收费云服务或用户提供办公账号 |
| 多人阶段 | 完整 PostgreSQL 适配 + 真实身份/权限 | 当前 PostgresStore 不是可直接替换的完整存储实现 |

具体依赖版本由 M1-01 探测本机 Python/Node 后选定、验证并锁定；此后不静默升级。不要求用户安装 Docker，不依赖 `%TEMP%` 残留包。首次准备依赖可联网，安装完成后的 M1 本地功能不依赖外部模型服务。

官方依据：Vite 提供 React/TypeScript 模板并有明确 Node 版本要求（[Vite Guide](https://vite.dev/guide/)）；FastAPI 文档展示请求范围数据库会话（[SQL Databases](https://fastapi.tiangolo.com/tutorial/sql-databases/)）；Python 文档说明 SQLite 连接线程限制及事务行为（[sqlite3](https://docs.python.org/3/library/sqlite3.html)）。采用上述组合是本项目的实施决定，不是这些文档对本项目的验收背书。

## 6. 最小数据与事务设计

先实现 M1 所需表，不提前落地整个公司全部业务实体。每个业务记录必须带项目范围、稳定 ID、时间和版本；金额/数量必须有单位或币种。

| 数据对象 | 必需内容 |
| --- | --- |
| Project / Decision | 名称、项目范围、运行模式、用户口径、来源、确认状态 |
| FileAsset / FileRevision | 服务端 SHA-256、字节数、受控存储键、原始名称、来源关系、格式/校验状态 |
| Issue / IssueAction | 来源文件及定位、类型、影响、处理状态、理由、记录人 |
| Estimate / EstimateLine / EstimateRevision | 原始预算映射、数量来源、单位、单价口径、行类型、不可变修订 |
| CalculationRun | 输入修订、参数快照、公式版本、逐项结果、警告、计算时间 |
| Job / JobAttempt | 作业类型、输入哈希、状态、租约、尝试次数、错误、输出引用 |
| Artifact | 文件修订、字节哈希、输入版本、生成器版本、用途、草稿/过期/发布状态 |
| CommandRecord / AuditEvent | 请求指纹、幂等键、目标版本、结果、操作者及业务变化 |

M2 在此之上加入受限 SpatialUnit、GeometryRevision、QuantityItem 和版本化 TraceLink，实现几何到量价的追踪。M1 用明确的文件/修订引用，不能用无约束通用关系图替代必要字段。

事务约束：

1. 命令指纹、版本检查、业务修改、任务/事件写入和审计在同一个数据库事务提交；异常整体回滚。
2. 唯一幂等范围为组织/项目/命令类型/幂等键；同键同指纹返回原结果，同键不同指纹返回明确冲突。所有缓存和外部动作键也必须包含项目范围。
3. 更新时携带预期版本；旧版本返回冲突，不采用最后写入覆盖。
4. 不通过关闭 SQLite 线程检查来掩盖并发问题。使用短事务和线程内连接，后台 Worker 独立连接；超时和锁冲突需有明确处理。
5. 新关系存储与旧 JSON 快照实现分开。旧快照仅保留参考用途；若发现真实运行数据，先备份、清点并验证迁移，不静默删除重建。
6. 审计保存关键操作，不将本地追加记录冒称生产级防篡改审计。正式隔离审计和身份在多人阶段完成。

## 7. 接口与文件/任务设计

### 7.1 API 最小面

保持已有 `/api/v1` 前缀和命令入口，先更新 OpenAPI 再实现对应真实行为。下列是能力目标，具体 schema 必须复用既有契约中已有字段。

| 接口 | 目标行为 |
| --- | --- |
| `GET/POST /api/v1/projects` | 列表、创建项目；服务端分配 ID |
| `GET /api/v1/projects/{id}` | 概览和当前基线 |
| `GET /api/v1/projects/{id}/files` | 文件、版本、来源和处理状态 |
| `POST /api/v1/projects/{id}/uploads` | 创建受项目约束的上传会话 |
| `PUT /api/v1/projects/{id}/uploads/{upload_id}/content` | 有大小限制地接收真实文件流 |
| `POST /api/v1/projects/{id}/uploads/{upload_id}/complete` | 服务端校验已落盘字节，完成登记并创建处理任务 |
| `GET /api/v1/projects/{id}/files/{file_id}/content` | 安全预览或下载授权范围内的具体版本 |
| `GET /api/v1/projects/{id}/issues` | 可追溯问题清单 |
| `GET /api/v1/projects/{id}/estimates/{estimate_id}` | 原表映射、工作副本及修订 |
| `POST /api/v1/projects/{id}/commands` | 修改明细、试算、处理问题、创建导出等已注册业务命令 |
| `GET /api/v1/projects/{id}/jobs` | 任务进度、输入版本、错误和可用操作 |
| `GET /api/v1/projects/{id}/artifacts` | 成果列表和版本 |
| `GET /api/v1/projects/{id}/artifacts/{artifact_id}/content` | 返回真实成果文件，不能只有元数据 |

M1 新命令按实际需要登记，例如 UpdateEstimateLine、CalculateEstimate、RecordIssueDisposition、QueueReportExport、RetryJob、CancelJob。不得继续用通用 handler 只记一条事件即返回业务成功。只支持已实现命令；未支持能力返回明确说明。

本地试用采用服务器固定的本地身份和启动会话，不把客户端传入 actor_type 直接当授权事实；只绑定回环地址，限制 Host/Origin 和写请求会话。若要局域网多人使用，先完成对应身份和项目授权，不直接开放开发身份头。

### 7.2 文件生命周期

上传会话 → 暂存字节 → 服务端哈希/长度/格式检查 → 原件登记 → 按能力排队解析 → 派生预览/检查结果。

- 存储路径使用服务端 ID；不接受客户端任意绝对路径。文件名作为展示字段，不能决定落盘目录。
- 上传中断保留为未完成会话；不能生成“已扫描/可用”的假记录。仅做格式检查时如实写格式已检查，不冒充病毒扫描通过。
- 同项目同内容可以引用已有文件字节，但保留每次导入来源记录。跨项目不通过重复提示泄露文件存在性。
- 已有宁波样本通过一次性、幂等的种子导入进入 `var/`，不是前端写死的一组数据；重复启动不覆盖用户编辑。
- CAD 解析作为可选后台作业。现有项目可直接载入已生成的结构化结果；任意新图不具备定位条件时明确记录未支持/需定位，不能套用宁波坐标或资产 ID。
- 不执行上传文件内脚本/宏；不在 M1 实现任意压缩包递归执行。

### 7.3 作业生命周期

```text
queued → running → succeeded
             ├─ retryable → queued（新 attempt）
             ├─ failed
             └─ cancelled
```

Job 与 Attempt 分开。每次尝试锁定输入哈希，保存心跳/租约和错误。启动时回收过期 running 租约：确认已有有效成果则完成，否则按作业类型重排或进入可重试状态。不能因为已有失败结果就永久去重为“完成”。

文件生成使用临时文件、哈希校验、原子落位和成果登记；恢复时识别已落位但未登记的结果，避免同一作业重复产物。取消是持久状态，晚到结果不得覆盖取消；完成后的作业不能被伪装取消。已有参考工作流状态规则可复用，实际继续执行能力需另行实现并验证。

## 8. 报价与计算设计

本节为试算程序规则，税率为用户参数，不判断税法适用性。

- 成本加成：`未税售价 = 已知未税成本 × (1 + 加成率)`。
- 未税转含税：`含税金额 = 未税金额 × (1 + 税率)`。
- 含税拆税：`未税金额 = 含税金额 ÷ (1 + 税率)`；未税结果按分舍入后，`税额 = 含税金额 − 未税金额`，保持合计一致。
- 所有输入金额声明含税/未税；成本与售价口径不同且无法统一时，显示不可比较，不输出伪精确利润。
- 施工与设计加成分开，不把 20% 和 60% 叠加到同一成本项。
- 原预算已有单价视为来源报价，不默认它是内部成本，也不再次自动加成。用户选择“按成本试算”后才使用明确成本字段。
- 原预算重算总价与 600,000 元合同目标分别显示；有差额就显示差额，不自动修改每行单价凑数。
- 缺失成本/数量保留 unknown，合计注明已知部分；不显示“实际利润”。
- 原表基础费、主材、家具、运费和安装按行类型建模；小计/汇总行不重复参与合计。已列家具与备注排除家具的冲突保留问题记录。
- Decimal 全程计算，金额默认 ROUND_HALF_UP 到分；行汇总、拆税、展示的舍入阶段固定并记录公式版本。CSV 中保留完整单位与口径。

CalculationRun 固定输入明细修订、税率、加成规则及公式版本。修改明细创建新修订、使旧计算和导出标记过期；旧成果仍可查看。导出默认取当前成功计算版本，不能导出一个看似最新但引用旧明细的报告。

## 14. 接管、状态更新与范围控制

后续 AI 每次开始：读取约定、交接、状态和本文 → 核对上次证据 → 选择最早依赖已满足的未完成任务 → 实施 → 验证 → 更新状态 → 继续下一项。

`PROJECT_STATUS.md` 记录当前里程碑、任务状态、已通过 UAT 数/总数、证据路径和下一动作。本文保持设计基线，不复制一份会漂移的任务状态。需要调整设计时追加短决策记录，说明原因、影响和新验收条件；普通实现细节不用再次要求用户确认。

每次交付用中文说明：新增了什么可操作能力、如何打开、怎样验证、仍有哪些限制、用户现在是否需要参与。只有真正可运行时才给运行地址；只有实际产生文件时才声称可下载。

不允许以完成更多文档、补齐更多 Schema、反复研究同一 CAD 或等待三个历史项目代替当前功能交付。M1 完成后进入用户试用，同时在没有依赖冲突时继续 M2；不要把用户尚未反馈视为停止所有开发的原因。
