## 准入检查中修复的问题

1. **验收重复提交失败**：原代码先检查状态是否为 analyzed，首次 accepted 后即拒绝同键重放。现在先核对幂等请求及目标，重复请求保留同一版本和单条验收事实，异内容冲突。
2. **不同变更共享分析/验收键**：增加 change_id 和 event_type 核对，防止相同指纹误用其他变更的事件。
3. **空检查项可验收**：按计划要求至少一个非空检查项，并继续要求证据及责任操作者。
4. **重复订单行/并发数量风险**：收货和分派拒绝同一请求中的重复行，写事务在读取数量之前取得 SQLite 写锁；两个并发 6 套收货请求只能成功一个，两个并发 4 套分派请求只能成功一个。低于四位小数精度、量化后变为零的数量也被拒绝。
5. **页面变更成果下载缺少身份**：按钮现在发送带当前身份的下载请求，浏览器实际取得三份文件并匹配字节数及 SHA-256。
6. **资料漂移**：纠正“下一步 M4/M4-03”、交接中的旧下一阶段和 PostgreSQL“只需注入驱动”说法。实际后端仍是 Python 标准库 HTTP server，FastAPI 目标未落地，生产服务器迁移明确纳入 M5-04。

## M5-01 已实现

- 版本化 SQLite 015 迁移：个人账号、项目成员、会话、登录限制及身份审计。
- 个人账号密码登录，独立随机盐及 PBKDF2-HMAC-SHA256；服务端只存会话令牌哈希，密码/令牌不回传到普通账号列表或审计。
- Cookie 为 HttpOnly/SameSite=Strict；写请求有 CSRF 和 Origin/Host 校验；8 小时绝对到期、30 分钟空闲到期，失败登录限流。
- 账号管理员管理本组织项目；普通账号只可访问已分配项目，区分负责人、编辑、只读。客户端自报组织、操作者或角色均不能代替数据库身份。
- 原件以及预算、空间、设计、变更成果使用同一请求授权边界；撤销项目角色、停用账号、退出后，下次访问立即拒绝，旧下载地址不能绕过授权。
- 登录页、创建账号、角色分配/撤销、停用/恢复页面已接实际 API；操作者使用真实用户 ID。
- `start-secure` 通过可信本机终端设置首位管理员，无默认密码、无公开注册、无外部采购/付款/正式发布权限。已配置账号的数据库拒绝显式降级到 local。

SSO/MFA、账号恢复、隔离防篡改审计、HTTPS/网络部署、后端全域 PostgreSQL 迁移不是本批完成项。标准库 HTTP server 继续只监听回环地址；此限制通过启动负例验证。

## M5-02 首批基础实施

本轮新增 `mvp/persistence/postgres/002_runtime_domains.sql`，将本机 SQLite 001—015 的运行域映射到 `rkd` schema：文件接收/原件、任务与问题、预算及计算、空间/工程量/报价、需求/设计、采购/收货/分派、变更/验收，以及 M5-01 账号/成员/会话/登录限制/身份审计。项目级表统一启用 RLS；会话通过账号组织范围隔离，登录限制默认只允许服务角色访问；身份审计增加 append-only 触发器。

新增 `mvp/rkd_mvp/postgres_migrations.py`，按连续版本发现迁移，创建 `rkd.schema_migration`，每个版本单独事务提交，迁移失败回滚并关闭连接；会兼容现有 001 文件的外层 `BEGIN/COMMIT`。新增 `mvp/rkd_mvp/postgres_repository.py`，在一次 RLS 租户事务内执行项目初始化、命令幂等、聚合版本锁定、领域事件和 Outbox 写入。

M5-02 专项 16/16 通过：`mvp/tests/test_postgres_migrations.py` 覆盖迁移连续性、事务归一化、记录及运行域/RLS 契约；`mvp/tests/test_postgres_boundary.py` 覆盖 RLS 上下文、回滚、租约及 Repository 原子写路径。当前机器没有可调用的 PostgreSQL 服务或客户端，因此尚未执行真实迁移、非 owner 连接、RLS 并发/重启和 SQLite→PostgreSQL 对账；这些是 M5-02 后续实证，不由静态 SQL 或假连接替代。

新增适配测试后全量回归为 **131/131**，0 跳过、0 失败；前端 `npm --prefix web run build` 成功，仍只有既有 PDF.js 大包 warning。
