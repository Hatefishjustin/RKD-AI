## 0. 架构审查结论与修订

本轮审查确认总体分层正确，但发现以下问题会在开始写代码后造成高成本返工，已在本版封口：

| 级别 | 审查发现 | 本版调整 |
| --- | --- | --- |
| P0 | 业务事务、审计、幂等和 Outbox 的原子边界不明确 | 明确单库事务边界；安全审计使用本地可靠队列，A3/审批/付款失败关闭 |
| P0 | 租户隔离主要依赖应用过滤，数据库管理员/服务身份边界不够具体 | 所有项目表强制 RLS/等价行级策略，应用角色禁用 owner/superuser 绕过 |
| P0 | 工作流引擎只描述“持久化”，没有最低能力和升级规则 | 增加 WorkflowRuntime 能力门槛、版本兼容、事件历史和恢复验收 |
| P1 | 事件至少一次投递没有死信、毒消息和安全重放边界 | 增加 DLQ、重放隔离、事件 Schema 校验和聚合分区顺序 |
| P1 | 审计“篡改检测”没有具体防护 | 增加哈希链、签名检查点、不可变副本和职责分离 |
| P1 | 备份没有不可变存储、密钥隔离和恢复后风险控制 | 增加 Object Lock/WORM 等价能力、独立备份密钥、恢复目录和 A3 停用 |
| P1 | 外部调用只有超时/对账原则，没有 `unknown` 状态 | 增加外部动作状态机和人工对账入口，禁止盲目重发 |
| P1 | API、容量和恢复目标没有绑定可执行验收 | 增加 P95、队列、恢复、权限和故障注入验收指标 |

本版仍不锁定具体云厂商或工作流产品；只有通过第 16 节能力验收的实现才可进入生产。

## 1. 架构结论

V1 采用三个可独立发布的运行平面：

1. **业务平面**：网站、API、命令网关、业务模块、权限和查询投影。
2. **自动化平面**：持久化工作流、Agent 编排、定时器、人工任务、队列和回调处理。
3. **专业执行平面**：CAD/BIM/渲染/QTO/文档执行器、隔离工作节点和许可证资源。

业务平面默认采用模块化单体，而不是一开始拆成大量微服务。模块通过应用服务、命令、领域事件和查询接口协作；只有当容量、权限、部署频率或供应链风险确实不同，才将模块拆为独立服务。数据库和文件存储的归属边界从第一天就按未来拆分设计。

### 1.1 不可破坏的边界

- Agent、工作流、执行器和外部适配器没有生产业务表写权限。
- 业务事实只能由归属模块的命令处理器写入，并在同一事务中写入审计和事务发件箱。
- 派生搜索、向量、报表和通知失败不能回写或伪造业务事实。
- 外部动作只能通过 `CommandEnvelopeV1` 和外部适配器执行；适配器回调必须经过收件箱去重和对账。
- 原始文件、成果文件、发布清单和审计事实不可被“重新生成”覆盖。

## 2. 逻辑拓扑

```text
浏览器 / PWA / 门户
        |
   Web Edge / BFF
        |
API 层 -> 认证与策略 -> 查询投影
        |
命令网关 -> 业务模块 -> 事务发件箱 -> 事件总线
    |              |                  |
    |              +-> 业务数据库     +-> 工作流编排器
    |                                   |       |
    +-> 外部动作授权                    |       +-> Agent 运行器
                                        |       +-> 人工任务
                                        |       +-> 执行器调度器
                                        |
                              专业执行器隔离节点
                                        |
对象存储/隔离区/归档/NAS <---- 成果、原件、日志、清单
搜索索引/向量索引/报表 <----- 可重建派生数据
审计存储/监控/告警 <--------- 不可变审计和运行证据
```

外部系统只通过适配器端口接入：身份提供商、消息平台、对象存储、NAS、模型供应商、CAD/BIM 云 API、供应商/支付系统。外部平台的 ID 和状态不直接成为业务主键。

## 3. 运行单元和模块边界

### 3.1 Web Edge 与 BFF

- 提供内部工作台、老板审批中心、客户门户、供应商/施工方受限门户和移动端 API。
- 处理 TLS 终止、会话/令牌校验、请求大小和频率限制、CSRF/CORS、上传预签名 URL 和基础审计。
- 不实现业务状态迁移；写操作全部转成内部命令。
- 查询根据角色和项目范围返回投影，不把内部数据库表直接暴露给前端。

### 3.2 身份、组织与项目上下文模块

负责 `Organization`、`User`、`ServiceIdentity`、`PartyRole`、项目成员、项目类型能力包、数据分级和授权上下文。它不拥有报价、采购或模型事实，只提供可验证的身份和授权决策。

### 3.3 Project Kernel

Project Kernel 是跨域配置和版本基础设施的归属模块，负责：

- `Project`、项目生命周期和项目能力包绑定；
- `ConfigurationItem`、`ItemRevision`、`BaselineSet`、`ChangeSet`、`ImpactRecord`；
- `TraceLink`、`ExternalReference`、对象映射和引用完整性；
- 版本并发控制、基线锁定、替代/失效和迁移影响报告。

Project Kernel 不拥有需求、报价、采购和施工字段，只保存跨域关系和公共版本事实。

### 3.4 业务模块

| 模块 | 主要事实 | 唯一写入边界 |
| --- | --- | --- |
| Requirements | Requirement、Constraint、Assumption、Decision、DesignBrief | 需求事实和 G2 准备包 |
| Concept/Design | DesignIntent、SpatialProgram、SpatialOption、SpatialPlan | 设计方向、空间候选和选定方案 |
| Model/Artifact | Element、Assembly、ModelRevision、DrawingSet、RenderScene、Artifact | 专业成果状态和表示引用 |
| Commercial/Finance | BOQ、Quote、Contract、Invoice、Payment、CostEntry、Reconciliation | 数量、价格、合同和财务事实 |
| Procurement | Supplier、MaterialProduct、PurchaseRequest、PurchaseOrder、Receipt、Allocation | 采购、收货、分派和供应商事实 |
| Site Operations | WorkPackage、ProgressReport、SiteIssue、Inspection、PunchItem | 现场进度、质量问题和验收事实 |
| Change/Handover | ChangeSet、ImpactRecord、Acceptance、HandoverPackage、Warranty | 变更、交付和售后事实 |

每个模块公开命令处理器、领域事件、只读查询和迁移器；禁止其他模块绕过命令写表。

### 3.5 Workflow Orchestrator

负责长流程和等待状态：项目闸口、生产批次、AgentTask、ExecutorJob、人工任务、计时器、重试、补偿和升级。工作流状态不等于业务状态；工作流只能根据领域事件推进，不能自行把对象标记为 approved/published/effective/paid。

工作流定义锁定主版本，实例保存实际使用的规则、能力包、契约和任务版本。修改流程只影响新实例或显式迁移实例。

#### 3.5.1 WorkflowRuntime 最低能力

工作流实现必须支持：

- 持久化事件历史、长时间计时器、暂停/恢复、信号/人工任务和活动取消；
- 确定性重放或等价的状态恢复；工作流代码升级有兼容版本和迁移策略；
- 活动超时、指数退避、最大尝试次数、补偿、心跳和检查点；
- 事件因果链、业务幂等键、租户/项目限流和死信处理；
- 运行状态、等待原因、下一动作和人工接管可查询；
- 备份恢复后不会重复命令、通知、发布、下单或付款。

不得用进程内定时器、内存队列或自建不可恢复的“任务表轮询”替代持久化工作流运行时。选型必须用一个跨月模拟流程、一次节点重启、一次版本升级和一次重复事件回放验证。

### 3.6 Command Gateway

命令网关是所有写入和外部动作的统一入口，执行顺序：

```text
解析命令 -> 查注册表 -> 校验契约
-> 身份/组织/项目授权
-> 聚合版本和状态守卫
-> 风险/职责分离/数据策略
-> 幂等检查
-> 业务模块事务处理
-> command_record + 业务状态 + 业务审计摘要 + Outbox 原子写入
-> 返回命令结果和领域事件引用
```

网关拒绝未知命令、旧版本目标、越权项目、缺少证据、过期授权和外部副作用未对账请求。Agent 返回的命令提案不能携带最终授权证明；网关必须重新生成 `CommandEnvelopeV1`。

命令处理事务的边界固定为同一个业务数据库事务：`command_record`、聚合状态、业务事实、业务审计摘要、幂等索引和 Outbox 必须一起提交或一起回滚。安全审计、日志和指标不能假装与业务数据库跨系统原子；它们先写入同库可靠队列或本地追加缓冲，再异步写入隔离安全审计存储。审批、A3 外部动作、付款和发布如果无法写入业务审计摘要，必须失败关闭；普通读取事件允许可靠补写但必须告警。

同一 `idempotency_key + command_type + target_id` 只能对应一个最终命令结果；重复请求返回原结果，不重新执行处理器。

### 3.7 Agent Runtime 与 Executor Dispatcher

- Agent Runtime 只接收 `AgentTaskV1`，通过上下文构建器得到最小证据，返回 `AgentResultV1`。
- Executor Dispatcher 只接收 `ExecutorJobV1`，为执行器分配隔离节点、许可证和临时凭证。
- 两者都以队列和工作流活动运行，不能依赖进程内内存保存业务状态。
- 运行器崩溃后从任务状态和检查点恢复；重复投递使用业务幂等键，运行 ID 独立。

## 4. 数据和存储架构

### 4.1 主业务数据库

V1 默认使用 PostgreSQL 兼容的关系数据库作为业务事实源。实际产品可替换具体托管服务，但必须支持事务、行级并发控制、JSON Schema 约束、时间/版本索引、加密和可恢复备份。

数据库按模块使用逻辑 schema 或表前缀隔离，并记录 owner、迁移版本和公开访问方式。模块之间不直接共享写模型；跨域查询通过查询接口或投影。

所有含 `organization_id` 或 `project_id` 的表必须启用数据库行级安全策略（RLS）或能力等价的强制行级隔离。每个请求在受信任的连接中设置不可伪造的组织/项目上下文；应用连接角色不能成为 schema owner、数据库 superuser 或绕过 RLS。迁移角色、运维 break-glass 角色和应用角色分离，break-glass 使用短期授权并强制安全审计。

跨域只读查询也必须经过范围策略；禁止使用一个未带租户条件的“万能查询用户”。权限测试必须覆盖 API、后台任务、搜索、向量、对象存储令牌和恢复后的数据库连接。

必须具备的公共表/逻辑对象：

```text
organization / project / party_role / identity
configuration_item / item_revision / baseline_set / change_set
trace_link / external_reference / object_mapping
command_record / domain_event / outbox_message / inbox_message
workflow_instance / activity_run / human_task / timer
artifact / artifact_revision / transmittal / download_grant
audit_event / security_audit_event
```

事件和审计字段分别遵循 `contracts/v1/event-envelope.schema.json` 与
`contracts/v1/audit-event.schema.json`；业务数据库中的摘要与安全审计存储中的完整证据通过 `audit_id`、哈希和检查点关联。

业务模块专属表不能替代这些公共对象，也不能把 JSON 扩展字段当成无限制业务表。

### 4.2 对象存储和隔离区

对象存储分为 `quarantine`、`raw`、`working`、`published`、`archive` 五类逻辑区域：

- `quarantine`：未通过安全扫描或来源不可信的文件，执行器不可访问。
- `raw`：原始上传和外部回调原文，只读、带哈希和来源。
- `working`：作业临时输入输出和可重建中间成果，按作业租约清理。
- `published`：已批准发布的成果和 Transmittal，不覆盖，只能替代或撤回。
- `archive`：归档副本和恢复材料，异步同步到 NAS/异地存储。

文件访问使用短期下载令牌，令牌绑定组织、项目、Artifact、版本、用途、范围和过期时间。业务 API 不把本地路径、永久 URL 或长期密钥返回给浏览器、Agent 或执行器。

### 4.3 派生存储

搜索索引、向量索引、缩略图、预览、报表、通知和驾驶舱都是派生数据。它们保存来源 revision、策略版本和重建时间，支持按对象/项目/组织删除和完整重建。派生存储不可作为审批、报价、付款或模型版本的事实源。

### 4.4 队列和事件总线

V1 使用持久化队列承载工作流活动、执行器作业、通知、索引和对账任务；使用事务 Outbox 防止业务事务成功但事件丢失。每条消息至少带：消息 ID、事件/活动类型、项目、聚合、相关/因果 ID、幂等键、版本、重试次数、可见时间和数据分级。

队列分为高风险外部动作、业务命令、专业执行器、低优先级派生任务和通知五类。高风险队列默认串行或按项目限流，防止重复下单、重复付款和单项目资源占满。

事件采用至少一次投递，按 `aggregate_id` 分区保证同一聚合的顺序；消费者必须先校验事件 Schema、租户范围和 `aggregate_version`，再写 Inbox 和业务结果。连续失败的消息进入带原始载荷、失败原因和重试历史的 DLQ，不能无限重试。

重放只能进入隔离的 replay 队列，默认禁止通知、外部动作和业务写入；需要产生业务命令时必须由责任人创建新的正式命令并重新授权。事件保留期、DLQ 保留期、重放操作者和结果均写入审计。毒消息、未知事件版本和跨租户消息必须告警。

## 5. API 和事件接口

### 5.1 查询接口

- 面向前端的查询使用资源/投影 API，返回对象 ID、revision、状态、权限范围、数据日期和缺失情况。
- 大文件、模型、图纸和表格使用预签名下载或流式查看器，不把二进制放进事务 API。
- 查询结果带 `correlation_id`、`project_context_version` 和 `as_of`，避免用户误把历史投影当作当前事实。
- 报表必须同时返回计算公式/口径、样本分母、数据日期、缺失数和版本。
- 列表接口必须分页并限制最大页大小；文件、日志、模型对象和审计查询使用游标，不允许无界导出占满 API。
- 返回字段按数据分级和用途脱敏；内部底价、提示词、密钥引用和其他客户标识不能通过前端“隐藏”代替服务端过滤。
- 查询缓存必须绑定组织、项目、角色、对象版本和策略版本；权限变化或撤回/删除事件触发失效。

### 5.2 命令接口

- 命令必须来自 `command-registry.json`，请求包含目标对象、期望版本、payload、幂等键和因果来源。
- 成功只表示命令已被归属模块接受；真正的下游变化由领域事件和工作流观察。
- 返回 `accepted`、`rejected`、`duplicate`、`conflict`、`needs-human` 等稳定结果，不用 HTTP 200 掩盖业务拒绝。
- 外部动作返回内部命令 ID 和对账状态，不直接承诺第三方已成功。
- 写接口要求 `Idempotency-Key`；长任务返回可查询的命令/工作流 ID，不能让 HTTP 请求等待执行器完成。
- 所有拒绝返回稳定错误码、当前版本、所需角色/证据和相关审计 ID；不得在错误消息泄漏跨租户对象存在性。

### 5.3 事件接口

事件使用 [event-registry.json](../contracts/v1/event-registry.json) 的名称和版本。消费者必须使用 Inbox 去重、按聚合版本检查顺序，并允许重复投递、延迟投递和未知可选字段。破坏性事件变化使用新主版本。

## 6. 工作流架构

### 6.1 工作流类型

| 类型 | 示例 | 特性 |
| --- | --- | --- |
| 短事务流程 | 草稿创建、状态迁移 | 一个命令事务内完成，失败立即返回 |
| 人工闸口流程 | G1-G5、专业复核、付款核验 | 持久等待、超时升级、不能自动批准 |
| 生产批次流程 | BIM、效果图、施工图、BOQ、报价 | 并行分支、交叉检查、部分失败和定向重跑 |
| 外部对账流程 | 下单、回调、付款、文件发布 | 超时查询、幂等、补偿和人工对账 |
| 迁移/恢复流程 | 版本迁移、备份恢复、重建索引 | 分阶段、可暂停、产生影响报告 |

### 6.2 重试和补偿

- 可重试错误只包括暂时网络、限流、节点资源和执行器临时不可用；指数退避带随机抖动。
- 权限、格式、规则、许可证无效、版本冲突和质量失败不自动无限重试。
- 外部动作超时必须先查询第三方结果，再决定重试、对账或人工接管。
- 补偿是新业务命令或对账记录，不是把数据库回滚成假历史；已经发生的订单、付款、发布和施工事实不可抹除。
- 每次重试保存原始运行 ID、原因、参数、执行器版本和成本。

### 6.3 人工任务

人工任务至少包含任务类型、责任角色、项目/对象范围、输入证据、目标修订、到期时间、升级路径、允许动作和完成标准。人工完成必须产生正式命令或新修订，不能直接编辑 Agent 运行日志。

## 7. 权限、租户和职责分离

### 7.1 授权模型

采用 RBAC + ABAC：

```text
allow = role_permission
      AND organization_scope
      AND project_scope
      AND object_state_policy
      AND risk_limit
      AND data_classification_policy
      AND separation_of_duties
      AND feature_flag
```

权限判断由策略服务/应用服务执行，前端隐藏按钮不构成安全控制。每次授权结果记录策略版本、输入上下文、结果、决策 ID 和有效期。

### 7.2 角色和入口

| 角色 | 默认入口 | 可见范围 | 高风险限制 |
| --- | --- | --- | --- |
| 老板/授权审批人 | 审批中心、驾驶舱 | 被授权项目和经营摘要 | 只能批准授权闸口，不能替代专业签字 |
| 主案/专业责任人 | 内部工作台 | 负责项目和专业对象 | 负责设计/质量确认，不能自批受控外部动作 |
| 项目经理 | 项目工作台 | 项目进度、任务、风险和发布 | 不能代替财务/法定签署 |
| 商务/财务 | 商务成本 | 合同、发票、付款、成本 | 不能修改模型几何和替代审批 |
| 采购/现场 | 采购施工 | 供应商、订单、收货、问题 | 收货与付款核验职责分离 |
| 客户 | 客户门户 | 自身项目已发布内容和任务 | 不可见内部成本、底价、提示和其他项目 |
| 供应商/施工方 | 受限门户 | 被分派订单、图纸和任务 | 只能提交事实和回执，不能改批准基线 |
| 系统管理员 | 管理后台 | 系统健康和配置 | 不因管理员身份自动获得业务内容 |
| Agent/Executor | 服务身份 | 当前任务的最小生产包 | 无数据库写权、无通用管理员权、无 A4 |

### 7.3 租户隔离

组织、客户、供应商和项目是权限域，不允许仅靠前端过滤实现隔离。业务查询和命令必须携带组织/项目上下文；数据库查询、对象存储令牌、搜索索引和向量检索都必须重复执行范围过滤。跨项目模板和公司知识采用显式共享授权，不因同一公司自动可见。

### 7.4 职责分离矩阵

至少防止以下同一身份闭环：

| 动作链 | 必须分离 |
| --- | --- |
| 采购申请 -> 订单批准 -> 收货确认 -> 付款核验 | 申请、批准、收货、付款核验 |
| 报价计算 -> G3 批准 -> 合同签署 | 计算、经营批准、法定签署 |
| 模型生产 -> 专业复核 -> G4 批准 -> 发布 | 生产、复核、批准、发布 |
| Agent/规则配置 -> 生产启用 | 配置、批准、启用 |
| 权限授予 -> 审计删除/导出 | 授予、复核、数据导出 |

## 8. 审计和安全证据

### 8.1 业务审计

`AuditEvent` 至少记录：事件 ID、时间、组织/项目、主体身份、角色、命令/事件/任务、目标对象和版本、前后状态摘要、原因、证据引用、策略版本、相关 ID、IP/设备（适用时）和结果。敏感 payload 只存哈希/引用，不把完整密钥、提示上下文或其他客户资料写入普通日志。

### 8.2 安全审计

登录失败、权限拒绝、权限变更、批量导出、外部分享、下载令牌、文件扫描、提示注入、越权工具、A3 动作、停用开关、备份恢复和管理员操作写入单独安全审计流。每条安全审计包含前一条哈希、当前事件哈希和签名检查点；每日或每批次将检查点写入独立不可变存储。安全审计读取、保留策略、导出和密钥使用与业务管理员分离，业务管理员不能清除自己的安全证据。

审计链断裂、签名验证失败、检查点缺失或时间回拨必须触发 critical 告警；高风险动作在审计存储不可用时失败关闭。

### 8.3 审计保留

审计事件、业务事实、原始文件和派生索引分别遵循 `DataLifecyclePolicy`。删除、归档和法律冻结产生策略版本、范围、执行状态和证明；日志脱敏不改变事件的可审计关联。

## 9. 外部适配器和回调

所有第三方连接器实现统一端口：`authenticate`、`submit`、`query_status`、`receive_callback`、`reconcile`、`cancel_or_compensate`。业务模块不依赖第三方字段名，适配器保存映射版本和原始回执。

回调流程：

```text
接收 -> 验签 -> 保存原文和哈希 -> Inbox 去重
-> 解析适配器版本 -> 关联内部命令/对象
-> 更新对账状态或创建异常 -> 发布内部事件
```

回调签名失败、对象不存在、金额/数量不匹配和重复状态必须保留证据并进入异常队列。外部连接器的测试环境只能使用模拟账号和沙箱，不允许通过配置误连生产账号。

所有具有副作用的外部动作使用以下内部状态机：

```text
prepared -> authorized -> dispatched
-> confirmed | rejected | failed
-> unknown -> reconciling -> confirmed | rejected | manual-resolution
```

`unknown` 表示本系统无法证明第三方是否已接受，禁止直接重发。适配器必须提供查询/对账能力；若第三方没有查询能力，动作只能停留在人工确认，不得自动重试。

## 10. 部署拓扑和环境

### 10.1 环境

| 环境 | 数据 | 外部副作用 | 目的 |
| --- | --- | --- | --- |
| Dev | 合成/脱敏 | 全部模拟 | 本地开发和契约调试 |
| Test | 固定测试集 | 模拟适配器 | 自动化、状态机、权限和故障测试 |
| Staging | 脱敏金标准 | 沙箱/受控模拟 | 回放、迁移、灰度和恢复演练 |
| Production | 真实项目 | 受控真实账号 | 正式业务 |

环境之间使用不同凭证、密钥、队列、对象存储和域名。生产数据不能通过复制数据库直接进入开发或测试。

### 10.2 V1 部署单元

V1 最少拆成：

1. `web-api`：Web Edge、BFF、查询 API、命令入口和轻量应用服务。
2. `workflow-worker`：持久化工作流、Agent Runtime、人工任务和通知。
3. `executor-dispatcher`：专业作业队列、资源/许可证租约和回调收集。
4. `executor-node-*`：按能力拆分的隔离节点，不能与 API 共用生产凭证。
5. `data-services`：关系数据库、对象存储、队列、审计存储、监控和备份。

业务模块仍可部署在同一个 `web-api` 进程内；模块边界、数据库 owner 和事件接口按未来拆分保留。

### 10.3 高可用和容量

- Web/API 至少两个无状态实例，前置健康检查和限流；会话放在可恢复共享存储或使用短期令牌。
- 工作流和执行器按队列伸缩，单项目、组织和能力设置并发/成本配额。
- 专业节点按软件、GPU、许可证和数据区域分池；节点不可跨项目泄漏临时文件。
- 数据库先保障可靠备份和恢复，再评估读副本、分片和独立服务；不要用缓存替代事务一致性。
- 大文件上传使用分片/断点续传和后台扫描，不占用 API 请求线程。
- 以产品规格的 P0 目标作为初始 SLO：工作流月可用性 >=99.5%，常用项目页面 P95 <3 秒，普通保存 P95 <2 秒。正式容量以压测结果为准，并为 API、数据库、队列、对象存储和执行器分别设置饱和阈值。
- 压测必须包含单项目高峰、多项目并行、大文件上传、队列积压、重复回调、搜索/向量重建和执行器离线；超过阈值自动降级为排队或人工任务。

## 11. 备份、恢复和灾备

### 11.1 目标

沿用 V1 目标：核心业务数据 RPO 不超过 15 分钟，大文件 RPO 不超过 24 小时；核心工作台 RTO 4 小时内，归档大文件 RTO 24 小时内。目标必须通过实测演练确认，不是宣传指标。

### 11.2 备份矩阵

| 数据 | 备份方式 | 频率/保留 | 恢复要求 |
| --- | --- | --- | --- |
| 业务数据库 | 全量 + WAL/增量 + 加密异地副本 | 每日全量；持续增量；按策略保留 | 恢复到时间点并校验事务/事件连续性 |
| 对象存储 raw/published | 版本化、跨设备/区域副本、清单哈希、不可变保留/Object Lock 等价能力 | 按生命周期和法律冻结 | 抽样哈希、manifest、保留锁和权限一致 |
| Outbox/Inbox/工作流 | 数据库备份 + 队列重建 | 与核心数据同级 | 不重复业务副作用，恢复挂起活动 |
| 审计/安全审计 | 追加存储、篡改检测、隔离副本 | 独立保留策略 | 可检索、签名/链校验和权限一致 |
| 配置/契约/迁移 | Git/制品仓库/不可变发布包 | 每次发布和长期保留 | 可重建同一发布单元 |
| NAS 归档 | 异步副本，不作唯一事实源 | 每日同步 + 定期校验 | NAS 离线不阻断在线业务 |

备份密钥与生产数据密钥分离，恢复角色不能读取生产密钥库中的长期密钥。备份目录记录时间点、来源版本、加密密钥版本、校验状态、不可变截止时间和恢复测试结果；备份成功但无法独立恢复视为失败。

### 11.3 恢复顺序

```text
身份/密钥 -> 数据库时间点恢复 -> Outbox/Inbox 去重
-> 对象存储和清单 -> 工作流状态 -> 派生索引/报表
-> 外部适配器对账 -> 业务负责人验收 -> 恢复服务
```

恢复后先暂停 A3 外部动作和付款/下单队列，完成订单、付款、发布、文件和工作流对账后再解除停用。

### 11.4 必须演练

- 数据库丢失到指定时间点；
- 对象存储主区域不可用；
- NAS 离线；
- 队列重复投递和工作流中断；
- 密钥轮换后服务恢复；
- 执行器节点/许可证中心不可用；
- 误发布成果撤回和审计恢复。

每次演练保存实际 RPO/RTO、缺失项、人工步骤、修复责任人和复测日期。

## 12. 安全基线

- 所有外部访问使用 TLS；敏感数据静态加密；密钥由集中式密钥/秘密服务管理，不进入代码、提示词、契约或生产包。
- 服务间使用短期身份令牌和最小权限；执行器默认无网络，仅允许许可证/API 白名单。
- 上传文件先扫描病毒、宏/脚本、压缩包路径穿越和恶意格式；不可信文件停在 quarantine。
- 数据库、对象存储、搜索、向量、日志和备份都执行组织/项目范围过滤。
- 外部分享使用身份验证、有效期、水印、下载权限和撤回；分享行为写安全审计。
- 管理员、Agent、执行器和连接器不能绕过命令网关访问业务写模型。
- 对提示注入、越权工具、异常下载、批量导出、重复外部动作设置告警和全局停用。
- 依赖、镜像、插件、模板和字体保存摘要、来源、SBOM、许可证和漏洞状态。
- 身份提供商、密钥服务和令牌轮换必须有失效/恢复预案；离职、密钥泄露和设备丢失触发立即撤销。
- Break-glass 访问必须双人批准、短期有效、限定对象和命令范围，使用后自动生成复核任务。

## 13. 监控、告警和运行手册

### 13.1 指标

| 类别 | 必须监控 |
| --- | --- |
| API/网站 | p50/p95/p99、错误率、超时、请求大小、认证失败 |
| 工作流 | 活跃实例、等待时长、超时、重试、人工任务积压 |
| 命令/事件 | 拒绝率、版本冲突、Outbox 延迟、Inbox 重复、事件积压 |
| Agent | 成功/需人工/失败、成本、质量门、工具拒绝和停用 |
| 执行器 | 队列深度、运行时长、许可证、资源、质量失败、节点健康 |
| 数据 | 存储容量、扫描积压、索引延迟、备份成功、恢复校验 |
| 业务 | G1-G5 超时、采购延期、未对账金额、发布撤回、问题关闭 |

每个 P0 指标都要有目标、告警阈值、分母、采样范围、责任人和运行手册；SLO 连续消耗错误预算时停止扩大灰度，优先修复可靠性。

### 13.2 告警等级

- `critical`：安全事件、重复下单/付款风险、数据损坏、核心数据库/对象存储不可用，立即停用相关动作并通知负责人。
- `warning`：工作流积压、许可证不足、备份失败、质量门下降、对账异常，进入责任人队列并按时升级。
- `info`：普通完成、低风险重试和可重建索引延迟，不打扰老板。

每个告警都要有运行手册：确认方法、影响范围、停用开关、恢复/补偿步骤、证据保存、升级角色和关闭条件。

## 14. 发布、迁移和回滚

发布单元必须同时包含应用版本、数据库迁移、契约/事件注册表、权限策略、工作流版本、Agent/模型路由、执行器兼容矩阵、配置和功能开关。

发布顺序：

```text
契约兼容检查 -> 数据库 expand 迁移 -> 应用兼容版本
-> 自动测试/权限测试 -> 金标准回放
-> Staging 恢复演练 -> 低风险灰度 -> 生产扩散
```

- 破坏性字段/事件/状态变化使用新主版本和迁移器；旧项目继续使用锁定版本。
- 回滚优先恢复上一完整发布单元；数据库不可逆迁移必须先执行前向兼容方案。
- 功能开关按组织、项目类型、项目和风险级别控制，四级停用独立于应用发布。
- 迁移前生成影响报告；迁移后验证对象计数、版本、事件连续性、权限、文件哈希和业务指标。

## 15. V1 平台最小闭环

平台 MVP 与第 4 项统一模型的首条纵向链绑定：

1. OIDC 登录、组织/项目成员、RBAC+项目范围 ABAC。
2. 项目、文件上传/隔离扫描、版本和 Artifact 清单。
3. Project Kernel：Revision、Baseline、TraceLink、命令网关和审计。
4. G2 工作流：需求/DesignIntent/审批/人工任务/超时升级。
5. 生产批次工作流：BIM manifest -> 效果图或图纸或 BOQ 至少两条分支 -> EX-14 交叉检查。
6. AgentTask/AgentResult、ExecutorJob/ExecutorResult、CommandEnvelope 和事件 Outbox/Inbox。
7. 一个模拟外部适配器：采购下单或文件发布，验证幂等、超时、回调和对账。
8. 数据库、对象存储、审计、监控和一次可重复的恢复演练。

第一版不接真实付款和正式生产下单；所有 A3 动作使用模拟适配器，直到权限、审计、对账和恢复验收完成。

## 16. 平台验收条件

- [ ] 未授权用户无法看到其他组织/项目的对象、搜索、向量和文件。
- [ ] Agent/Executor 无法直接写业务数据库，所有变更都有命令、版本、审计和事件。
- [ ] 同一命令、事件、回调和工作流重放不会重复业务副作用。
- [ ] G2/G3/G4/G5 目标变化会使旧审批和生产任务 `superseded`。
- [ ] 文件扫描失败不能进入执行器；发布文件与 manifest 哈希一致。
- [ ] 生产批次能独立重试分支，空输出不能通过交叉检查。
- [ ] 外部动作超时先查询/对账，不直接重发。
- [ ] 审计管理员不能删除自己的安全审计；批量导出和外部分享可追溯。
- [ ] 数据库、对象存储、队列、工作流和密钥恢复演练可重复，并达到 RPO/RTO 目标。
- [ ] 数据库迁移、契约升级和权限策略升级具备回滚/前滚方案。
- [ ] RLS/等价租户隔离覆盖 API、后台任务、搜索、向量、对象令牌和恢复连接，跨租户负例测试全部拒绝。
- [ ] 工作流运行时通过跨月等待、节点重启、版本升级、重复事件和 DLQ 重放验收。
- [ ] 审计哈希链和独立检查点可验证，管理员不能改写或删除安全证据。
- [ ] 外部动作的 `unknown` 状态、查询/对账和人工解决路径已通过超时故障注入。
- [ ] 压测证明 P95、队列积压、并发配额和降级策略达到产品目标。

## 17. 实施顺序

### 阶段 A：共同底座

- 真实专业执行器选型和隔离节点；

### 阶段 D：扩展

- 客户/供应商/施工门户；
- 真实采购和文件发布适配器；
