# AI 自主完成率、图纸错误率、成果一致性和人工干预评估体系

版本：V1.0  
日期：2026-09-19  
机器记录合同：`contracts/v1/evaluation-observation.schema.json`

## 1. 评估目的

本体系回答四个问题：

1. 系统真正独立完成了多少工作，而不是调用了多少次 AI。
2. 生成的模型、效果图、施工图和报价是否正确、相互一致并有证据。
3. 人工时间花在计划内审批，还是花在纠错、救火和重新制作。
4. 某项能力是否可以从影子运行升级为受监督自动，再升级为低风险自主运行。

指标不能用于包装“无人化”。五个人工闸口属于计划内治理，不算自动化失败；隐瞒问题、遗漏任务、把未知填成 0 或把返工交给人工，则必须计为失败或干预。

## 2. 统计基本单位

### 2.1 任务观察单元

每次可独立验收的工作形成一个 `EvaluationObservationV1`，例如：

- 一次需求结构化；
- 一个空间方案生成；
- 一个模型版本生成；
- 一张图纸或一个图纸包生成；
- 一次工程量计算；
- 一个报价版本生成；
- 一个采购异常处理；
- 一个施工问题闭环。

观察单元必须记录项目、任务类型、风险等级、自动化等级、开始/完成时间、人工干预、缺陷、一致性检查、证据覆盖、模型/执行器版本、重试、耗时和成本。

### 2.2 合格分母

自主完成率只对“系统在当时版本声明可以处理”的合格任务计算。以下情况不进入合格分母，但必须单独显示：

- 输入缺少合同规定的必填资料；
- 文件格式或项目类型不在当前能力声明中；
- 高风险任务按政策必须人工执行；
- 外部系统不可用且无替代路径；
- 用户取消或项目范围正式变更。

系统错误地拒绝本应支持的任务，不能从分母删除，必须记为失败。每次排除都要有标准原因码，禁止事后为了提高数字修改资格。

## 3. 自动化等级

| 等级 | 含义 | 是否可计入自主完成 |
| --- | --- | --- |
| Manual | 人工完成，系统只登记 | 否 |
| Assisted | 系统提供建议，人工主要制作 | 否 |
| Shadow | 系统独立产出但不影响业务，与人工结果比较 | 仅评估，不计生产自主 |
| Supervised | 系统完成，人工逐项复核后使用 | 可单列，不算完全自主 |
| Autonomous | 系统完成并通过自动校验，仅经过政策规定的闸口 | 是 |

自动化等级按“任务类型 + 项目类型 + 风险等级 + 版本”授权，不允许给整个 Agent 一个永久全局等级。

## 4. AI 自主完成率

### 4.1 核心公式

`自主完成率 = 自主接受任务数 / 合格任务数`

“自主接受”同时满足：

- 自动化等级为 `autonomous`；
- 结果被接受；
- 没有人工纠错、救援或手工绕过；
- 只允许存在政策规定的 `planned-gate`；
- 没有 E0/E1 缺陷逃逸到下一阶段；
- 所有强制一致性检查通过。

同时公布：

- 受监督完成率；
- 首次通过率；
- 失败率；
- 被拒绝/不合格任务率；
- 返工后接受率；
- 端到端直通率。

### 4.2 端到端直通率

`端到端直通率 = 从需求到目标发布全链无纠错完成的项目数 / 合格项目数`

任何中间环节需要人工重做、复制粘贴或手工重新录入，整条链不能算直通。计划内 G2/G3/G4 审批不破坏直通，但审批人修改成果则计为纠错。

### 4.3 分层公布

不得只公布一个总数。至少按以下维度拆分：

- 项目类型：企业空间、商业、办公、餐饮、酒店、住宅等；
- 阶段：需求、空间、模型、渲染、施工图、BOQ、报价、采购、施工、变更、交付；
- 风险等级：A0-A4；
- 自动化等级；
- 模型版本、执行器版本和规则版本；
- 新项目与历史回放。

## 5. 人工干预指标

### 5.1 干预分类

| 类型 | 含义 | 对自主完成的影响 |
| --- | --- | --- |
| planned-gate | G1-G5 等政策规定的审批 | 不算失败，单独计时 |
| clarification | 输入确实缺项或冲突后的补问 | 不自动算失败，评估补问质量 |
| correction | 人工修改系统产出 | 不算自主完成 |
| rescue | 系统失败后由人工接管 | 计失败和人工救援 |
| manual-bypass | 绕开系统完成 | 计失败并调查原因 |

### 5.2 指标

- 每任务人工分钟数，中位数和 P90；
- 每项目计划内审批分钟数；
- 每项目纠错分钟数；
- 每项目救援次数和分钟数；
- 每个已接受成果的人工修改字符、对象、图元或金额比例；
- 重复补问率；
- 人工复制/粘贴/下载/上传次数，目标为 0；
- 老板每项目非计划干预次数。

人工时间必须由系统任务开始/完成、编辑差异和审批操作共同记录，不能完全依赖人员事后填写。

## 6. 图纸和模型错误率

### 6.1 缺陷等级

| 等级 | 定义 | 示例 |
| --- | --- | --- |
| E0 致命 | 可能导致安全、法规、重大合同或施工事故 | 错误结构判断、消防安全错误、错误正式发布 |
| E1 重大 | 会导致返工、重大成本/工期偏差或无法施工 | 关键尺寸错、门洞冲突、漏主要构件、数量重大偏差 |
| E2 一般 | 局部专业错误，可在发布前修正 | 标注缺失、局部图模不一致、材料编码错 |
| E3 轻微 | 不影响功能和计量的表达问题 | 非关键排版、线型或文字样式问题 |

### 6.2 核心指标

- 每张图 E0/E1/E2/E3 数量；
- 每 100 个模型对象的几何/属性缺陷；
- 每 100 个标注的错误、缺失和重复数；
- 碰撞检查未解决数；
- 发布后缺陷逃逸率；
- 施工现场因图纸导致的 RFI、返工和签证数；
- 缺陷发现阶段和根因分布。

加权图纸缺陷分：

`(100×E0 + 20×E1 + 5×E2 + 1×E3) / 图纸张数`

该分数用于同类型、同深度、同检查标准的版本比较，不能跨项目类型直接排名。任一 E0 都阻止发布；E1 未关闭也阻止 G4。

## 7. 成果一致性

| 检查 | 分母 | 不一致示例 |
| --- | --- | --- |
| 需求-设计覆盖 | 已批准需求数 | 需求未落到空间、材料或验收条件 |
| 空间-模型一致 | 已批准空间对象数 | 面积、用途、邻接或净尺寸不一致 |
| 模型-图纸一致 | 可比模型对象/标注数 | 图纸漏对象、位置/尺寸/编号不一致 |
| 模型-BOQ 一致 | 应计量对象数 | 漏量、重复量、计量规则版本错 |
| BOQ-报价一致 | BOQ 项和报价项 | 数量、单位、价格快照、税或范围不一致 |
| 图纸-效果图一致 | 已锁定设计要素数 | 材料、门窗、家具、灯光或造型冲突 |
| 变更传播一致 | 应受影响成果数 | 已批准变更未传播或传播到错误版本 |

`一致率 = 通过的可比项 / 全部可比项`

每项必须记录容差配置。无法比较的项标记 `blocked/not-applicable`，不能当作通过。

## 8. 证据和未知项

- 证据覆盖率 = 有有效来源或人工确认的必需事实数 / 必需事实数。
- 未知保留率 = 正确保留为 unknown 的未知项 / 金标准未知项。
- 无证据断言率 = 无来源且未标为推断的事实数 / 系统事实总数。
- 来源漂移率 = 升级后同一输出指向错误/过期来源的比例。

目标不是消灭 unknown，而是不让 unknown 被伪造成 0、默认品牌、默认尺寸或已确认结论。

## 9. 效率、稳定性和成本

- 任务墙钟时间：中位数、P90、P99；
- 队列等待和执行时间分开统计；
- 首次成功率、技术重试率、质量重试率；
- 外部 unknown 率和平均对账时间；
- 每项目/阶段/任务的模型与执行器成本；
- 单个已接受成果成本；
- 工作流恢复成功率；
- RPO/RTO 实测；
- 执行器版本引起的回归率。

便宜但质量不合格的结果不计“成本节约”。成本比较必须以同等验收质量为前提。

## 10. 阶段门槛

| 指标 | 原型/回放 | 第一条生产链 | 正式生产扩大权限 |
| --- | ---: | ---: | ---: |
| E0 逃逸 | 0 | 0 | 0 |
| E1 发布前未关闭 | 允许研究样本，不可发布 | 0 | 0 |
| 强制一致性检查通过率 | >=90% | >=98% | >=99.5% |
| 来源覆盖率 | >=90% | >=98% | >=99.5% |
| 状态/消息恢复成功率 | >=95% | 100% 测试通过 | 100% 且演练通过 |
| 权限负例通过率 | 100% | 100% | 100% |
| 人工搬运次数 | 可观测 | 0 | 0 |
| 任务自主完成率 | 只建立基线 | 分任务类型设目标 | 连续 3 个以上项目达标才扩大 |
| 端到端直通率 | 不设目标 | 影子统计 | 连续多个同类项目稳定后启用 |

不为施工图、报价、合同和安全设置一个脱离项目复杂度的虚假“95% 自主”目标。先在每种任务类型建立基线，再由责任人批准具体阈值。

## 11. 采样和统计规则

1. 历史金标准、影子任务和真实生产分开统计。
2. 少于 30 个任务只显示原始数量和区间，不用单个百分比宣称稳定。
3. 使用滚动 30 天和最近 3 个项目两个窗口，同时保留全量历史。
4. 指标下降必须能定位到模型、执行器、规则、输入类型和版本。
5. 同一失败重试多次只算一个业务任务失败，但重试次数和成本分别统计。
6. 被人工提前中止的错误结果也计失败，不能因“未发布”从质量统计删除。
7. 发现标注错误后回溯修正金标准，并保留原标注版本和审批记录。

## 12. 防止指标作弊

- 不允许通过缩小“合格任务”定义提升自主率；能力范围变更必须版本化并事前生效。
- 不允许把人工编辑改名为审批；是否改变输出由差异记录判定。
- 不允许把失败任务拆成多个小成功任务或把多次重试重复计算成功。
- 不允许用平均值隐藏长尾；必须同时显示中位数、P90 和失败数量。
- 不允许只统计 AI 模块，不统计人工搬运、执行器失败和外部对账。
- 不允许用视觉相似度代替施工图尺寸、模型拓扑或金额复算。

## 13. 评估流程

1. 冻结输入、金标准、容差、规则和版本。
2. 运行系统并自动生成观察记录。
3. 确定性校验器先检查状态、几何、金额、权限和一致性。
4. 专业人员只复核需要判断的样本，并记录缺陷和修改。
5. 系统汇总分层指标和置信范围。
6. 质量委员会决定保持、扩大、缩小或关闭自动权限。
7. 所有决定绑定指标快照、责任人、生效日期和回滚条件。

## 14. 老板驾驶舱最小视图

老板只需要看到：

- 当前项目处在哪个阶段，下一闸口是什么；
- 每个阶段自主/受监督/失败数量；
- E0/E1 缺陷和未解决重大风险；
- 需求-模型-图纸-BOQ-报价一致性；
- 计划内审批与非计划纠错时间；
- 工期、成本、模型调用和重试异常；
- 最近版本变化及是否需要人工决定。

详细技术日志留给实施团队，不把所有普通告警推给老板。

## 15. 宁波协诚当前基线

当前真实样本已经可以建立“资料解析和 CAD 预处理”基线：原件指纹、57 层映射、模型/图纸空间可达性、主平面定位、块变换、范围排除、几何归组和闭合区候选均有结构化证据。当前 570 个候选归为 133 个几何组，并生成 70 个墙/天花/地坪闭合区候选，但最终对象数和可计量对象数仍为 0，因此不能据此宣称施工图自主完成或工程量准确。

下一次有效评估点是：专业拓扑验证和第二 CAD 引擎复核完成后，统计墙、门、家具、天花、地坪对象的正确率、漏检率、人工修订和处理时间。
