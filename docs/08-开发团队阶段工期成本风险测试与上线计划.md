# 开发团队、阶段、工期、成本、风险、测试和上线计划

> 2026-09-29 计划适用性修订：本文团队、周期和预算是早期多人建设情景，未据当前实施重新核算，不作为当前承诺或开工门槛。当前执行 [产品交付执行计划与设计](13-产品交付执行计划与设计.md) 的 M1—M5；用户无需先招聘完整团队、准备生产环境或补齐历史项目才能获得本地试用版本。

版本：V1.0  
日期：2026-09-19  
适用范围：企业空间第一条纵向生产链、宁波协诚施工期试点、正式生产 V1

## 1. 计划结论

这不是一个由一名程序员在 30 天内完成的低代码项目。建议采用“内部业务负责人 + 外部/招聘工程团队 + 现有专业人员验收”的混合方式：

- `8-12 周`：交付第一条可演示、可恢复、无真实外部副作用的纵向生产链。
- `4-6 个月`：在金标准项目上形成需求、空间、模型、效果图、施工图和报价的受控生产能力。
- `9-15 个月`：达到能够承担真实项目主要数字生产工作的正式版本。
- 宁波协诚先验证施工期资料、采购、问题、变更和追溯；下一个新企业空间项目验证从需求到正式成果的完整链路。

第一条生产链上线不等于全系统完成。任何阶段都不得用页面数量、Agent 数量或演示视频代替质量、恢复、权限和专业成果验收。

## 2. 团队配置

### 2.1 建议核心团队

| 角色 | 建议投入 | 主要责任 | 不可兼任的关键责任 |
| --- | ---: | --- | --- |
| 产品/实施负责人 | 1 人全职 | 范围、优先级、验收、跨团队推进 | 不能单独批准自己提出的高风险上线例外 |
| 技术负责人/后端架构师 | 1 人全职 | 业务 API、状态机、事务、权限、审计、代码质量 | 生产权限审计需另一人复核 |
| 前端工程师 | 1 人全职 | 内部工作台、客户/供应商入口、图纸/差异查看器 | 不能绕过 API 直接写业务数据库 |
| AI/工作流工程师 | 1 人全职 | Agent 编排、模型网关、评估、异常队列、成本治理 | 不能把模型输出直接写成正式业务事实 |
| CAD/BIM 自动化工程师 | 1-2 人全职 | DWG/IFC/参数模型、制图、QTO、专业执行器 | 不能自行批准施工图发布 |
| QA/测试自动化工程师 | 1 人全职 | 契约、回归、权限、故障、金标准和 UAT | 上线门槛不能由开发口头豁免 |
| DevOps/安全工程师 | 0.5-1 人 | 环境、CI/CD、监控、密钥、备份和恢复 | 不能与日常开发共用生产管理员账号 |
| 室内设计专业负责人 | 0.5 人内部投入 | 图纸、模型、效果图、材料和专业验收 | 必须对 G2/G4 保持人工签字责任 |
| 商务/财务责任人 | 0.2-0.5 人内部投入 | 报价、税、利润、合同、成本和付款口径 | 不允许 Agent 代替 G3 审批 |

最低可行配置是 5 名全职工程人员加内部专业负责人兼职。低于该配置可以做原型，但无法同时保证专业执行器、业务平台、安全、测试和上线质量。

### 2.2 用户、实施团队和系统各做什么

| 参与方 | 需要做的事 |
| --- | --- |
| 用户/老板 | 指定内部责任人；确认五个人工闸口；提供金标准项目和账号；确认税/利润/合同口径；参加阶段验收 |
| 现有设计与商务团队 | 标注金标准；解释专业例外；验收效果图、施工图、工程量和报价；在影子运行阶段记录修订 |
| 实施团队 | 开发、迁移、测试、部署、监控、培训、回滚和缺陷修复；不得要求业务人员人工搬运系统数据 |
| 系统 | 自动采集、结构化、编排、生产、校验、交接、提醒、留痕和恢复；在高风险节点停下等待责任人 |

## 3. 阶段和工期

| 阶段 | 计划周期 | 核心交付 | 退出门槛 |
| --- | ---: | --- | --- |
| P0 标准与金标准 | 第 1-6 周 | 数据字典、图层/材料/报价标准、3 个历史项目、验收标注 | 关键对象有负责人；金标准可重复回放 |
| P1 平台底座 | 第 3-10 周 | 身份、项目数字线程、文件版本、工作流、审计、异常中心 | 租户隔离、幂等、重启恢复、备份恢复通过 |
| P2 第一条纵向 MVP | 第 5-12 周 | 需求到空间/模型/图纸/BOQ 的结构化交接和模拟发布 | 单项目端到端无人工搬运；不产生真实副作用 |
| P3 空间/BIM/效果图 | 第 3-6 月 | 空间规划、参数化模型、材质/灯光/相机和批量渲染 | 企业空间金标准达标；G2 前不发布 |
| P4 施工图/工程量/报价 | 第 5-9 月 | 确定性制图、QTO、价格快照、报价与交叉校验 | 图模量价一致；G3/G4 权限和回滚通过 |
| P5 采购/施工/变更/交付 | 第 7-11 月 | 订单、收货、分派、问题、变更、验收和售后 | 宁波试点至少完成一次真实受控闭环 |
| P6 稳定化和扩类 | 第 10-15 月 | 性能、安全、灾备、住宅/商业等新模板 | 连续多个项目满足第 9 项指标才扩大自动权限 |

阶段允许重叠，但同一专业能力不得跳过金标准、影子运行和灰度直接进入生产。

## 4. 里程碑和验收责任

| 里程碑 | 验收人 | 关键证据 |
| --- | --- | --- |
| M0 架构基线冻结 | 产品负责人 + 技术负责人 | 模块边界、命令/事件、数据归属和威胁模型 |
| M1 平台底座可恢复 | 技术负责人 + QA | 重启、重复消息、跨租户、备份和恢复报告 |
| M2 第一条链路演示 | 老板 + 专业负责人 | 单次输入、自动交接、模拟成果、失败恢复和审计 |
| M3 专业生产可用 | 设计负责人 | 金标准差异、图模一致、效果图和制图质量报告 |
| M4 商务生产可用 | 商务/财务负责人 | 工程量、税、报价、成本和利润独立复算 |
| M5 受控真实上线 | 老板 + 安全/技术负责人 | UAT、权限、安全、回滚、灾备和培训签字 |

## 5. 成本规划

以下是建设预算带，不是供应商报价。假设在中国境内采用混合团队，金额含开发、测试和项目管理，不含公司现有人员工资、正式 CAD/BIM 商业授权、云渲染大规模消耗和硬件采购。

| 预算包 | 范围 | 建议预算 |
| --- | --- | ---: |
| A：8-12 周第一条纵向链路 | 5-7 人核心团队、隔离环境、模拟适配器、一个真实样本回放 | `45-100 万元` |
| B：4-6 个月专业生产基线 | 加入 CAD/BIM/渲染执行器、3 个金标准项目和预发布环境 | 累计 `120-260 万元` |
| C：9-15 个月正式生产 V1 | 完成施工图/报价/采购/施工/灾备/安全和多项目灰度 | 累计 `220-480 万元` |
| 年度基础设施与运维 | 云资源、对象存储、监控、备份、模型调用和常规运维 | `12-40 万元/年` 起 |

预算控制规则：

1. 每阶段单独立项和验收，不一次性承诺全部 15 个月费用。
2. 商业软件、模型 API、短信/钉钉、渲染和云资源按实际供应商报价单独列项。
3. 模型调用成本按项目、阶段、Agent、重试原因分别归集。
4. 需求变更必须生成对工期、成本、质量和回归范围的影响记录。
5. 不以削减测试、安全、备份或 CAD/BIM 专业工程师来压低首期报价。

## 6. 资源和环境

### 6.1 环境隔离

- `local`：开发人员本地，使用模拟数据和模拟外部动作。
- `test`：自动测试、契约回放和故障注入，不接真实客户/供应商。
- `staging`：脱敏真实样本、UAT、迁移和回滚演练。
- `production`：真实业务数据，最小权限、独立凭证、审计和备份。

### 6.2 NAS 定位

现有 NAS 可作为原始 CAD、模型、图片、合同和归档副本，但在阵列、SMART、容量、断电、异地备份和恢复实测完成前：

- 不作为 PostgreSQL 主库；
- 不作为唯一对象存储或唯一备份；
- 不直接暴露 SMB/WebDAV 到公网；
- 不承载本地大型 AI 或生产渲染主负载。

## 7. 风险登记册

| 编号 | 风险 | 概率/影响 | 预防 | 触发后的动作 |
| --- | --- | --- | --- | --- |
| R01 | 把演示当生产 | 高/致命 | 明确原型、影子、灰度、生产状态 | 停止外部发布，重新走上线门槛 |
| R02 | 金标准不足 | 高/高 | 至少 3 个完整企业空间项目 | 限制自动权限，只做影子运行 |
| R03 | DWG/BIM 兼容差异 | 高/高 | 双引擎/原软件抽样、版本锁定 | 降级为人工复核，不生成施工状态 |
| R04 | AI 幻觉进入正式成果 | 中/致命 | 结构化契约、确定性执行器、规则校验 | 隔离成果、关闭对应 Agent、回放审计 |
| R05 | 报价/税/利润口径错误 | 高/致命 | 固定公式、价格快照、财务审批 | 阻止 G3，独立复算并开商业异常 |
| R06 | 权限或跨客户泄漏 | 中/致命 | RLS、对象授权、负例测试、最小权限 | 全局停用、吊销凭证、事件响应 |
| R07 | 重复下单/重复发布 | 中/致命 | 幂等键、Outbox/Inbox、对账 | 冻结外部动作，进入 unknown 对账 |
| R08 | 长流程中断或升级丢状态 | 中/高 | 耐久工作流、版本化迁移、重放 | 使用旧版本 Worker 恢复或受控迁移 |
| R09 | 团队继续只用微信 | 高/高 | 钉钉固定入口、移动端极简、正式状态只在系统生效 | 培训并记录旁路，阻断无记录发布 |
| R10 | NAS/数据库单点故障 | 中/致命 | 3-2-1 备份、不可变副本、恢复演练 | 启动灾备，验证 RPO/RTO 后恢复 |
| R11 | 供应商 API/授权变化 | 高/中 | 适配器隔离、能力注册、替代供应商 | 切换适配器或降级任务 |
| R12 | 成本失控 | 中/高 | 项目/Agent 配额、缓存、批处理、告警 | 暂停高成本任务，人工批准扩容 |
| R13 | 专业责任边界不清 | 中/致命 | 五个闸口和签字责任 | 停止发布，补责任人和版本证据 |
| R14 | 范围无限扩张 | 高/高 | 企业空间优先、变更控制 | 延后非核心类型，不污染主链路 |

## 8. 测试策略

| 层级 | 必测内容 | 生产门槛 |
| --- | --- | --- |
| 单元测试 | 公式、状态守卫、几何变换、权限决策、序列化 | 核心规则 100% 分支覆盖目标；无阻断缺陷 |
| 契约测试 | API、命令、事件、Agent、执行器、适配器 | 所有支持版本 100% 通过 |
| 集成测试 | PostgreSQL、对象存储、工作流、消息、身份 | 重试、超时、重复和重启均可恢复 |
| 金标准回放 | 需求、模型、图纸、BOQ、报价、渲染 | 误差满足第 9 项分级阈值 |
| 权限测试 | 客户、供应商、施工方、跨组织和管理员 | 高风险越权 0 容忍 |
| 安全测试 | 恶意文件、提示注入、密钥、依赖和审计 | 致命/高危问题清零 |
| 故障注入 | 网络中断、回调丢失、执行器崩溃、磁盘/服务不可用 | 不丢状态、不重复副作用、可人工接管 |
| 性能/容量 | 并发项目、大文件、批量渲染、队列积压 | 达到容量模型且有退化策略 |
| 备份恢复 | 数据库、对象存储、NAS、密钥和配置 | 实际恢复达到批准的 RPO/RTO |
| UAT | 五个人工闸口和关键业务场景 | 每项有责任人、证据和签字 |

当前仓库的自动测试只证明参考骨架和部分 CAD 数据链可执行，不等同于上述生产测试全部完成。

## 9. 缺陷等级和停工条件

| 等级 | 示例 | 处理规则 |
| --- | --- | --- |
| S0 致命 | 数据泄漏、错误正式发布、重复下单、审计可篡改 | 立即停用相关能力并回滚 |
| S1 高 | 图模量价不一致、错误税额、任务丢失、恢复失败 | 不得进入下一闸口 |
| S2 中 | 可绕过但影响效率或局部质量 | 明确期限修复，可受控灰度 |
| S3 低 | 文案、非关键交互或观察性问题 | 纳入普通迭代 |

生产上线要求 S0/S1 为 0；S2 必须有负责人、到期日、影响范围和经过批准的临时措施。

## 10. 上线流程

1. 冻结候选发布版本和依赖清单。
2. 运行单元、契约、集成、金标准、权限、安全和恢复测试。
3. 在 staging 使用脱敏真实项目完成 UAT。
4. 演练数据库迁移、对象存储切换、工作流版本兼容和回滚。
5. 第一周只开放内部只读和低风险 A0/A1 能力。
6. 第二阶段开放可撤销的 A2 内部动作，外部动作仍模拟。
7. 选择一个新企业空间项目影子运行，与人工成果并行比较。
8. 指标连续达标后，按项目和风险等级逐项开放真实外部动作。
9. G2、G3、G4、重大变更和 G5 始终保留授权人员确认。

## 11. 回滚和应急

- 应用采用可回滚版本和向后兼容数据库迁移；破坏性迁移分两次发布。
- 工作流 Worker 按版本并存，在建项目默认继续旧版本，不能强制热切换。
- Agent、执行器、项目和全局均有停用开关。
- 真实外部动作进入 `pending/confirmed/rejected/unknown`，unknown 必须对账，不能盲目重试。
- 回滚后保留全部审计、失败输入和成果版本，不删除证据。
- 至少每季度演练一次数据库恢复，每半年演练一次完整灾备；重大架构变化后追加演练。

## 12. 上线验收清单

- [ ] 客户需求只录入一次，后续环节通过结构化生产包自动交接。
- [ ] 需求、空间、模型、效果图、施工图、BOQ 和报价可追溯到同一基线。
- [ ] 客户、供应商、施工方和内部角色权限负例全部通过。
- [ ] 报价、合同、成本、发票、付款和税没有混用状态。
- [ ] 重启、超时、重复消息和外部 unknown 状态均可恢复。
- [ ] 金标准、专业复核和图模量价交叉校验达到第 9 项门槛。
- [ ] 数据库、对象存储和 NAS 已完成实际恢复演练。
- [ ] 五个人工闸口、责任人、替补人和超时升级均已配置。
- [ ] 监控、告警、值班、停用和回滚流程已演练。
- [ ] 用户能在老板驾驶舱看到项目、质量、成本、工期和 AI 运行状态。

## 13. 立即行动

实施团队当前可以继续完成代码、数据合同、测试、环境模板和真实样本回放。需要用户参与的下一批事项只包括：指定内部责任人、提供至少 3 个完整历史企业空间项目、确认税和利润口径、提供生产账号/授权，并参加阶段验收。未到相应阶段前不要求用户重复提供施工图中已有的信息。
